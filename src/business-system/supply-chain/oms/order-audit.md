# 审单与挂起

> 本页描述通用 OMS 在接单之后、占库存之前的审单。规则示例用于学习，启用哪些规则以实际业务为准。

审单回答：这张单现在能不能发。映射失败是资料问题，停在异常待处理；映射成功但业务上不适合自动发，停在挂起，等人或等规则放行。

## 审单位置

```text
幂等接单 → 映射客户、商品、组织、业务模式
  → 自动审单
      → 通过：进入支付或信用放行
      → 挂起：等待人工或补充条件
      → 驳回：关闭或退回渠道，并说明原因
```

本专栏的默认是审单通过并且放行之后才寻仓、锁定。审单阶段不占用可售库存。如果业务要求「先锁再审」，必须写明锁多久、挂起超时如何释放，避免库存被挂起单占死。

## 常见自动规则

| 规则 | 命中后 | 原因 |
| --- | --- | --- |
| 地址无法解析到配送范围 | 挂起 | 寻仓和快递都依赖收货地 |
| 收货信息缺失 | 挂起 | 无法生成出库和运单 |
| 黑名单客户或地址 | 挂起或驳回 | 风险订单不自动发 |
| 金额、数量超过阈值 | 挂起 | 大额单人工确认 |
| 买家或卖家备注含约定关键词 | 挂起 | 备注里常有改地址、延迟发货、赠品要求 |
| 商品停售、单位无法换算 | 挂起 | 不能猜 SKU 或数量 |
| 指定仓库无货且不允许改仓 | 挂起 | 留给缺货策略，不直接超卖 |

规则按固定顺序执行，并记录命中了哪一条。一单多条命中时全部留下，避免只处理第一个原因、放过后面的问题。

自动通过的订单仍要满足[支付与放行](./payment.md)的条件。零售未支付通过审单后进入待支付，不是直接待履约。

## 挂起与放行

挂起单保存原始请求、命中规则、责任人和超时时间。人工可以：

- **放行**：重新走一遍自动规则。条件仍不满足则继续挂起。
- **补资料后重试**：补地址、补映射、补备注处理结果，再审。
- **驳回关闭**：未支付直接关闭；已支付则转入退款，不发货。

人工改地址、改商品、改数量时，走[改单与拦截](./order-change.md)，不在审单页直接改数量而不留痕。

超时仍无人处理的挂起单要有去向：继续等待、自动取消或通知渠道。不能无限挂起。

## 赠品和备注

赠品是审单里的一个策略，不是订单里凭空多出来的行。规则命中后增加赠品行，赠品行有自己的 SKU、数量和零金额或约定金额，并标记来源规则。赠品同样占用库存、参与寻仓。主品取消时，赠品是否一并取消要写在规则里。

备注不自动改订单。备注提示改地址时，应挂起，由人工或改单流程修改收货信息。不要靠解析一句自由文本就更换仓库或商品。
