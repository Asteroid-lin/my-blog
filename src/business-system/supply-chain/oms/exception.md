# 异常中心

> 异常中心是跨订单、库存、履约、售后和财务的处理视角，并不表示项目已有一个独立的“异常中心”服务。

## 业务目的与处理原则

异常处理要回答：**哪笔业务停在何处、外部系统是否已执行、谁来恢复、恢复后如何核对结果**。每个异常至少关联原业务单、来源系统、处理阶段、错误原因、重试次数、当前责任方和最终处理结果。

## 典型异常与恢复方向

| 场景 | 首先核实 | 恢复方向 |
| --- | --- | --- |
| 重复下单或支付回调 | 来源单号、支付流水、已有订单状态 | 幂等返回已有结果，避免重复建单或入账 |
| 主数据映射缺失 | 渠道商品、客户、组织或仓库编码 | 补齐有效映射后重放原请求 |
| 审单挂起超时 | 命中规则、责任人、是否已锁定 | 补资料后重审；若有预锁则先释放 |
| 支付超时或已关单又支付成功 | 关单状态和支付流水 | 关单不再发货，支付成功转退款 |
| 库存不足或锁定失败 | 当前可售、渠道配额、锁定流水和候选仓 | 换仓、部分发货、等待补货或按规则取消 |
| 出库下发超时 | WMS 是否已受理同一业务请求号 | 查询后重试同一请求或撤销占用 |
| 拦截结果不明 | 对端是否已拣货或已出库 | 查实后再释放；已出库则转售后 |
| 出库失败或部分出库 | 已发数量、未发数量和包裹状态 | 释放未发占用、改仓或人工处理 |
| 物流/退款回传丢失 | 对端真实状态与本地最后事件 | 补拉事件、幂等回放并对账 |
| 超过最晚发货时间 | 履约任务、包裹和渠道回传记录 | 优先发货或按渠道规则取消并退款 |

## 处理闭环

```text
发现异常 → 固定原始请求与业务单号 → 判断对端是否已执行
  → 分类为可重试、需补资料、需人工决策或不可恢复
  → 在同一业务标识下重试/补偿 → 核对订单、库存及外部结果
  → 记录处理人、时间、原因并关闭
```

自动重试应有次数与间隔限制；业务校验错误不应无限重试。人工修改业务状态前，先核实 WMS、支付或财务实际结果，避免“本地已取消，对端仍已发货”。补偿动作自身也需幂等，并留下流水。

人工强审、强发、强关单都属于补偿，必须留下操作人、原因和对端查询结果。本地改成已取消之前，先确认没有出库、没有第二张有效运单。
