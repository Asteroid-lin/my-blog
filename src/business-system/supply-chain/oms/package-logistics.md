# 包裹、运单与回传

> 本页补上出库之后的对象：包裹和运单。物流轨迹以承运商为准，仓内出库以 WMS 为准，OMS 负责把两者和订单行对上。

发货完成要能回答：哪一行的多少数量，装在哪个包裹里，由哪张运单承运，渠道看到的状态是什么。

## 对象关系

```text
履约任务 → 一次或多次出库回传 → 包裹
包裹 → 关联订单行及数量 → 通常一张运单
运单 → 揽收、在途、签收、拒收
```

一单多包、一包多行都正常。合包时一个包裹关联多个订单的行。拆单时一个订单对应多个包裹。

包裹上的数量之和，不能超过履约任务已分配数量。WMS 回传部分出库时，只为实际出库数量建包裹，剩余数量留在原任务或新任务上。

## 出库回传到包裹

```text
WMS 按业务请求号回传出库
  → 幂等：同一出库事件不建第二个包裹
  → 核对 SKU 与数量不超过已分配
  → 生成包裹和行明细
  → 结清对应库存锁定，扣减实物
  → 向渠道回传这部分已发货
```

回传数量小于分配数量，订单进入部分发货。回传数量大于分配数量，拒绝这次回传并进入异常，不先把多出来的数量记成已发。

没有 WMS 的供应商直发，由供应商回传发货数量和运单，OMS 同样生成包裹。没有包裹的「订单已发货」无法处理部分发货和售后。

## 运单

承运商在[履约中心](./fulfillment.md)选定。选定之后才申请运单号。运单号与承运商一起唯一。

电子面单是向承运商申请运单号和打印数据的动作。申请要用业务请求号幂等，避免一个包裹打出两张有效运单。申请失败可以换承运商或挂起，已经出库的包裹不能没有承运信息就回传渠道，除非渠道允许稍后补运单，并且有补回传时限。

发货前检查：

- 收货地址在承运商配送范围内
- 不在禁发区域，商品不在禁运清单
- 代收金额、保价、重量体积符合该承运商的要求

检查失败就换承运商或挂起。不要先把货交给无法派送的运单。

## 轨迹回传

揽收、在途、签收、拒收更新运单状态，不反向修改出库数量。签收可以作为订单完成条件之一。拒收不自动增加可售库存，货回到仓库并质检后，才按退货入库处理。

物流轨迹延迟或丢失时，按运单号向承运商补拉，不凭本地猜测改成已签收。

## 回传渠道

渠道关心的是发货状态和运单，不是 WMS 内部波次。回传内容至少包括：渠道订单号、本次发货的行和数量、承运商、运单号。

部分发货就部分回传。全部行的应发数量都有包裹之后，再回传整单已发货。重复回传同一包裹要被渠道或 OMS 的出站记录挡住。

平台通常有发货时效。超时未回传运单会带来处罚或自动退款。履约任务应记录最晚发货时间，超时进入[异常中心](./exception.md)，而不是只在报表里显示。
