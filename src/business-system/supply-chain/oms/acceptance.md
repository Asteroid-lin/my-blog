# 测试与上线验收

> 本页是未来 OMS 的验收计划，不是已经执行的测试报告。当前仓库只能验证文档与站点构建；下表涉及数据库、并发和真实对端的用例需在后端及联调环境实现。

## 四层验证各自证明什么

| 层次 | 验证对象 | 不能据此宣称 |
| --- | --- | --- |
| 规则验证 | 数量守恒、金额分摊、状态迁移、候选仓排序 | 数据库并发和外部接口可靠 |
| 数据库集成验证 | 唯一约束、事务回滚、竞争占用、任务领取 | WMS 或支付方支持真实幂等 |
| 契约和故障模拟 | 超时、重复、乱序、冲突、崩溃恢复 | 生产外部系统一定符合模拟行为 |
| 沙箱/试运行验收 | 真实鉴权、字段、查询、拦截及对账 | 超出已验证店铺、仓库和业务模式的范围 |

## 统一基础数据

使用[业务场景与单据推演](./business-scenarios.md)中的 O1001：A 3 件、B 1 件，总支付 500 元；W1 有 A 2、B 1，W2 有 A 1。每个用例使用隔离数据或重置到明确检查点，记录测试请求、外部结果和数据库明细。

## 场景验收矩阵

| 编号 | 触发与故障注入 | 必须得到的结果 |
| --- | --- | --- |
| A01 接单去重 | 同时提交同一店铺同一外部订单 10 次 | 一张订单、一组行；返回相同业务号 |
| A02 幂等冲突 | 相同 requestId 修改数量后再次提交 | 明确冲突，原快照及数量不变 |
| A03 支付先到 | 先接支付，后接订单，再重复支付通知 | 待关联事件可恢复；仅一笔支付事实与一次放行 |
| A04 资料缺失 | 删除 SKU 映射后接单，再补映射重放 | 原始请求可追溯，补齐后不重复建单 |
| A05 最后一件 | 可售 1，两个独立订单并发各占 1 | 仅一个成功；余额、占用与流水一致 |
| A06 分配中断 | 多行占用中间制造事务失败 | 按整单原子策略全部回滚；无孤立占用或下发任务 |
| A07 提交后崩溃 | 本地分配提交后、发送前终止进程 | 重启扫描待发送记录；只形成一个外部业务任务 |
| A08 响应丢失 | WMS 接单成功但 OMS 未收到响应 | UNKNOWN 保留占用；按原请求查询/重试，无双发 |
| A09 重复出库 | P1 重发；同明细换 eventId 再发 | 出库 A 2 件只扣一次，渠道回传任务不重复建 |
| A10 出库越界 | F1 的 A 已发 2，再发一条新的 A 1 明细 | 拒绝业务应用并留异常，不能超过分配量 |
| A11 取消竞态 | 出库回调和同一数量的取消同时执行 | 同一件不能既确认为取消又记出库；未知等裁决 |
| A12 部分取消 | P1 已发 A 2，只拦截 F1 的 B 1 | 仅 B 释放并退 200；A 的发货事实不变 |
| A13 迟到回调 | 出库后收到旧接单状态；退款后收到旧处理中状态 | 不回退状态，不重复占用或退款 |
| A14 占用到期 | WMS 状态未知时触发过期扫描 | 发起查询并保留占用，不直接释放 |
| A15 退款竞争 | 同一原支付/售后同时申请两笔合计超额退款 | 成功与处理中总额不超过两层可退额度 |
| A16 退款超时 | 退款方成功，OMS 响应丢失，再次查询/重试 | 沿用同一退款号；只退一次，未知期间额度不释放 |
| A17 退货质检 | A 1 件分别按良品、残次两组用例收货并重发 | 良品才回补可售，残次单独登记；均只记一次 |
| A18 完整案例 | 完成拆仓、部分出库、B 取消、A 退货 | 已发 3、取消 1、未发 0、已退 1；退款 300 元 |
| A19 租约接管 | 执行器 A 停顿，B 接管，A 恢复写结果 | A 的旧 token 写入失败；对外重复靠业务号去重 |
| A20 快照交错 | 快照已含一次出库，再投递该出库事件 | 按水位/业务明细不重复扣减；无水位进入核对流程 |
| A21 越权操作 | 客服访问未授权店铺或执行退款审批 | 查询与命令均拒绝；批量和导出同样拒绝 |
| A22 对账修复 | 丢一条回调，补拉并重放两次 | 差异可发现，补齐一次后复核关闭 |
| A23 错过调度 | 停机跨过重试时间后再启动 | 历史到期任务仍被扫描，不依赖恰好命中时间槽 |
| A24 回退开关 | 暂停新下发后接收在途任务出库 | 不产生新下发；既有事实仍入账并完成对账 |

A06 对应本次分配请求采用全有或全无策略。若启用“允许部分分配”，另建用例验证成功部分、缺货部分和下发任务有明确逐行结果，不能混用两个验收预期。

## 补充业务场景验收

以下是本轮补齐业务的验证计划。启用对应业务时才执行其扩展用例；未启用时也要验证入口明确拒绝或挂起。原 A01—A24 仍用于一期核心链路。

| 编号 | 场景 | 必须得到的结果 |
| --- | --- | --- |
| B01 接单补拉 | 推送和补拉重叠，分页中断后恢复 | 一张来源订单；分页齐全后才推进水位 |
| B02 取消先到 | 先接渠道取消，再补拉原订单 | 关联取消标记并核对结果，不自动放行发货 |
| B03 合法改单 | 渠道新版本改址，随后旧版本迟到 | 新修订可追溯；外发任务先拦截，旧版不覆盖 |
| B04 组合库存 | K=A×1+B×2，可用 A5/B7 | 展示最多 3 套；原子锁组件，父行不再次扣库存 |
| B05 赠品重审 | 已含渠道赠品，OMS 重审两次 | 不重复赠送；缺货按明确赠品策略处理 |
| B06 组合退货 | 退一个子件，随后重放同一申请 | 不超子件批准金额，父子金额不重复汇总 |
| B07 调拨短收 | 调出 10，实收 8，余 2 待核实 | 目的仓只增加实收；在途/差异保留 2 |
| B08 供应与取消 | 采购未到时客户取消，之后到货 | 关闭需求；到货不重新激活已取消订单 |
| B09 预售少到 | 承诺 10，良品入库 6，回调重发 | 最多转现货 6，剩余 4 可跟进，不重复转换 |
| B10 尾款迟到 | 未付尾款关单后收到成功付款 | 保留资金事实并处置退款，不重新发货 |
| B11 交期日历 | 跨截单时间、周末及假日 | 按节点日历计算，原承诺不被最新预计覆盖 |
| B12 齐套约束 | 一行缺货且订单要求一起交付 | 不下发可用部分，已占用部分按策略限时处置 |
| B13 直发未知 | 供应商超时后迟到接受 | 不提前改派，不生成两份有效交付 |
| B14 自提并发 | 两终端对同一凭证同时提同一件 | 仅一次核销，不伪造运单，不与 POS 双扣 |
| B15 信用竞争 | 两笔 800 元订单争用 1000 元额度 | 只依据原子授权放行，不能两笔都通过 |
| B16 分批交付 | 100 件分 40/60，两次授权/出库回传重复 | 计划总量不超 100，数量与额度只转换一次 |
| B17 售后新发 | 原买发 1，再换发 1，重复审批 | 原销售初次已发仍为 1，售后新发 1，库存去向可核对 |
| B18 先换后退 | 新货已发、旧货未回 | 不回补旧货库存，售后保留未收尾事项 |
| B19 丢件找回 | 已批准补发后原包裹又签收 | 同一案件追踪双交付，不再自动补发/退款 |
| B20 跨期账单 | 本期收款、下期退款，账单重复导入 | 区分时间性差异、不重复明细、不伪造修复 |
| B21 开票未知 | 开票方已成功但响应丢失 | 原申请号查询，不重复申请同一额度 |
| B22 效期和 SN | 库存不满足交付时剩余效期或 SN 已交付 | 阻止相应分配/出库，差异留存 |
| B23 召回 | 冻结批次有在库、已占用和已交付 | 定位不同去向并处置，缺少追溯信息单独列出 |
| B24 未启用模式 | 向一期发送组合、自提或预售订单 | 明确拒绝/挂起，不静默作为普通已付零售履约 |

各用例所需业务规则见[覆盖清单](./business-coverage.md)，扩展字段见[数据模型](./data-design.md)。本表尚未在 OMS 后端执行，不能作为生产验收通过证据。

## 每次执行保留哪些证据

```text
用例编号 / 代码版本 / 数据结构版本 / 执行环境
前置规则与数据 / 请求号与事件号 / 故障注入点
本地订单行、占用、流水、任务、退款前后值
对端查询结果 / 关键日志 / 对账结果
实际结论：通过、失败、阻塞、尚未验证
处理人 / 复核人 / 待处理事项
```

只看接口响应 200 不足以通过。要核对动作后数据库的数量、唯一记录和对端结果；任务重试成功之后还要核对是否残留占用、重复发货或重复退款。

## 容量和恢复验收

先填写峰值接单量、每单行数、多仓比例、库存热点分布、回调峰值、可接受积压和故障恢复时间，再构造与这些参数匹配的数据。记录吞吐、长尾延迟、库存锁等待、任务最老等待时间和恢复速度。未测量前不承诺固定 QPS。

重点压测同一 SKU 的竞争和同一订单上的并发取消/出库，而不仅是大量互不相关订单。确认限流或积压时，已接收的数据不丢失、重试不会放大成重复业务。

## 试运行准入

- 一期范围、库存权威和取消裁决已经确认，未实现业务在入口明确限制。
- 关键并发、重复和恢复用例有通过证据，阻塞项有负责人，不能把模拟通过当作真实对接通过。
- 真实对端能按业务号查询；无法自动裁决的结果有可执行的人工处理路径。
- 库存期初、未完成订单及在途任务已完成迁移核对。
- 权限、审计、脱敏、告警、停发开关和备份恢复完成演练。
- 试点期间按日核对订单行、库存、出库和退款；差异处理闭环后再扩范围。
