# 履约中心

履约中心决定“订单如何完成交付”，连接[订单中心](./order-center.md)、[库存中心](./inventory-center.md)、WMS、门店、供应商与物流。以下是通用学习模型；寻仓优先级和拆合条件落到具体系统时仍需按规则确认。已下发后的改地址、改仓和取消见[改单与拦截](./order-change.md)，出库之后的包裹和运单见[包裹、运单与回传](./package-logistics.md)。

## 业务流程与核心数据

```text
订单放行 → 读取收货地、商品属性和可履约库存
  → 筛选候选仓/门店/供应商 → 选择履约节点
  → 锁定库存或确认供应商承诺 → 决定拆合与配送方式
  → 生成履约子单/发货单 → 下发执行方
  → 接收出库、物流、签收或失败回传 → 更新履约结果
```

履约任务应关联原订单行、SKU、分配数量、库存组织、履约节点、外部仓编码、执行方、承运商、业务请求号与状态。多次分配、改仓和补发时，保留每次决策及撤销记录，便于解释订单数量去向。

## 寻仓与库存分配

候选节点至少需要满足服务区域、商品可发限制、仓库状态和可履约库存，再根据指定仓、时效、成本、库存深度选择。本专栏默认在选定仓后再校验并锁定库存，与[库存中心](./inventory-center.md)一致。若并发导致锁定失败，应重新评估剩余候选节点或进入[缺货与预售](./shortage-presale.md)，不能沿用过期库存快照。WMS 出库成功后结清锁定并扣减实物。

单仓且仓库在下单时已经确定的订单，可以跳过候选排序，在放行时直接锁定这一仓。这是同一条规则的特例，不是另一套库存口径。

硬约束过滤、截单日历、齐套策略、候选方案和原始承诺的保留见[交期承诺与履约规则](./delivery-promise.md)。缺货需要采购补充或仓间移货时，见[补货、采购协同与调拨](./replenishment-transfer.md)，不能把在途直接算成现货。

## 拆单与合单

一笔订单的商品需由不同仓、不同供应商或不同配送方式执行时，可形成多个履约子单；原订单和订单行仍保持统一交易关系。多个订单只有在客户、地址、仓库、时效、业务主体与配送限制等规则均允许时才可合并发货。合包不应改变原订单金额、售后归属或对账关系；部分取消、缺货和已出库任务要分别处理。

## 快递匹配与供应商直发

承运商选择需要考虑目的地、服务区域、商品体积或特殊属性、时效及费用规则。供应商直发需明确供应商商品映射、接单确认、可发数量、发货/物流回传与超时处理；不能仅因 OMS 仓库缺货就自动切换为直发。门店发货也应有独立的节点能力与状态回传规则。

直发承诺、门店拒单与 POS 库存、自提核销的完整流程见[供应商直发、门店发货与自提](./node-fulfillment.md)。这些节点复用履约对象，但不能全部套用“快递包裹签收”的完成条件。

## OMS 与 WMS 的边界

| OMS / 履约中心 | WMS |
| --- | --- |
| 决定由哪个节点发、分配多少、是否拆合及选用哪种物流服务 | 接收出库任务，决定波次、货位、拣货、复核和包装 |
| 管理履约任务与原订单、库存占用和物流单的关系 | 回传接单、出库数量、失败原因及必要包裹信息 |
| 处理改仓、取消、供应商直发和跨系统异常 | 处理仓内库存与作业异常 |

下发失败、对端已接收但响应丢失、部分出库及重复回传，都需要按同一业务请求号幂等处理，并以执行方状态核实后再释放或重新下发库存。

开发时用“订单行 → 分配 → 履约任务 → 包裹明细”保存数量去向，见[数据模型与约束](./data-design.md)。选仓规则保存版本和原因，外部发送通过可靠任务执行，见[模块架构与事务边界](./technical-architecture.md)。拆到两个仓后的部分出库与取消，可按[业务场景与单据推演](./business-scenarios.md)逐项核对。
