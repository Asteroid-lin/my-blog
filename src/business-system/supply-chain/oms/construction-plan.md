# OMS 建设范围与实施路线

> 本页是为未来自建 OMS 提出的建设基线，尚未对应已运行的后端。先按直营零售、现货实物商品设计第一版；经销、预售、代发等保留业务说明，按后续阶段接入。

## 第一版要交付什么

第一版的目标是：一笔渠道订单能够接入、审核、确认支付、占用库存、下发仓库、收到发货结果，并完成取消、退货、退款和异常处理。每一步能查到单据、数量、金额、操作人及外部结果。

| 范围 | 第一版基线 | 后续扩展条件 |
| --- | --- | --- |
| 主体 | 单经营主体，保留货主、组织、店铺、仓库标识 | 多租户、多主体结算需单独设计隔离和授权 |
| 订单 | 一个渠道适配器及人工导入，稳定外部订单号和行号 | 第二个渠道验证适配边界后再扩展 |
| 支付 | 接收可信支付结果、记录支付流水，不自建收银台 | 组合支付、信用额度、货到付款分别立项 |
| 商品 | 普通实物 SKU、整数件数、单币种 CNY | 组合商品、计重、批次及序列号需扩展行模型 |
| 库存 | 多仓数据模型，先单仓验证，再启用多仓分配；共享库存池 | 独占配额、预售库存、跨组织共享另行验收 |
| 履约 | 按仓拆任务、按行部分出库，暂不跨订单合包 | 合包必须保留原订单行、退款和运费归属 |
| 逆向 | 未发货取消、部分取消、退货退款、审核后的仅退款 | 换货、补发、维修使用独立关联单据扩展 |
| 集成 | WMS、支付、渠道接口先用可重放的模拟器联调 | 取得真实协议、凭证、沙箱后再认定集成完成 |
| 财务 | 输出发货、退款事实和差异清单 | 不把业务汇总当成会计入账或税务规则 |

单仓验证也要在订单行之外保留履约任务和包裹，否则后续多仓与部分发货会迫使核心数据重建。渠道配额的完整业务见[渠道库存](./channel-inventory.md)，第一版未启用独占配置时只走共享池。

完整业务目录见[业务覆盖与缺口清单](./business-coverage.md)。一期需要定义补拉、缺货出口、发货时限、物流异常和对账责任；组合商品、采购自动协同、预售、经销、直发、自提、换货及批次追踪按启用范围实施。未启用的场景在接单时显式拒绝或挂起，不能按普通零售路径静默处理。

## 把业务需求写成可以验收的动作

| 角色 | 需要完成的动作 | 系统必须留下的证据 |
| --- | --- | --- |
| 运营 | 查单、修复映射、审单、挂起、重新分配 | 命中规则、修改前后快照、处理结果 |
| 客服 | 查物流、申请取消、建售后、查询退款 | 申请数量、理由、拦截结果及退款状态 |
| 仓储对接人 | 查下发和回传差异、补拉仓库结果 | 外部任务号、原始事件、处理流水 |
| 财务对接人 | 核对支付、退款、发货及差异 | 原支付流水、退款请求号、行金额 |
| 管理员 | 配置店铺、仓库、规则及权限 | 配置版本、生效时间和操作审计 |

例如“支持取消”必须拆成：未分配可取消、已锁未发可释放、已下发需拦截、已出库转售后、部分成功返回逐行结果。不能用一个“取消订单”按钮掩盖这些区别。

## 按依赖推进里程碑

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| M0 业务基线 | 范围表、术语、规则决策、模拟订单、外部能力清单 | 明确库存权威、支付来源、取消裁决和退款条件 |
| M1 接单闭环 | 主数据、接单去重、订单头行、审单、支付流水、操作记录 | 重复导入不重复建单；支付先到也能补关联 |
| M2 发货闭环 | 库存余额与流水、占用、履约任务、WMS 适配、包裹回传 | 单仓后再多仓；部分发货、重复回调、下发超时可恢复 |
| M3 逆向闭环 | 取消与拦截、退货质检、退款申请与结果 | 取消不误释放；退款不超额；退货不重复回补 |
| M4 运行保障 | 权限、异常工作台、任务租约、对账、告警、回放 | 崩溃恢复和人工修复通过[场景验收](./acceptance.md) |
| M5 外部试运行 | 真实适配器、初始化库存、有限店铺或仓库试点 | 对端单据与本地核对一致；完成开关和回退演练 |

M1 就需要基本权限与审计，M2 就需要可靠任务；M4 是集中验证和完善，不是把这些能力拖到最后。阶段按退出条件推进，不以页面开发完成作为交付依据。

## 开发前必须做出的决策

| 决策 | 当前建议 | 需要补齐的输入 |
| --- | --- | --- |
| 实物库存来源 | WMS 为实物权威，OMS 维护镜像与占用 | 增量事件、版本、水位、全量快照能力 |
| 外部命令幂等 | 同一动作重试沿用原请求号 | WMS 和退款方能否按请求号查询 |
| 出库与取消冲突 | 已证实出库量不可取消，未知结果继续占用 | WMS 是否能确认“最终取消且不再出库” |
| 售后退款条件 | 未发货取消确认后退款；退货按质检结果审核 | 渠道对仅退款、运费及退货期限的规则 |
| 完成条件 | 履约完成与退款完成分别记录 | 签收来源、自动完成时限、争议处理 |
| 容量目标 | 先记录峰值接单、订单行数、SKU 数及回调延迟 | 用测量结果确定吞吐和恢复时限 |

无法取得最终取消结果、库存水位或退款查询能力时，要设计人工挂起和对账入口。不能用“默认成功”代替缺失的外部能力。
