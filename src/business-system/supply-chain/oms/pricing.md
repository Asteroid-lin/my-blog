# 金额与分摊

> 本页给出一套可学习的金额模型。优惠分摊有多种算法，这里采用「按商品金额比例分摊，尾差进最后一行」作为默认，便于部分发货和部分退款。

订单如果只有一个总价，部分发货和部分退款就无法解释每一行该确认多少钱。金额要在接单时分到订单行，并写进快照。

## 金额组成

| 金额 | 含义 | 放在哪 |
| --- | --- | --- |
| 商品标价 | 下单时的单价乘数量 | 订单行 |
| 商品优惠 | 单品折扣、满减分摊、优惠券分摊 | 订单行 |
| 商品成交金额 | 标价减去商品优惠 | 订单行，后面分摊的基数 |
| 运费 | 向客户收取的运费 | 先有订单级，再分摊到行 |
| 运费优惠 | 免邮、运费券 | 随运费分摊 |
| 应付 | 成交金额 + 实收运费 | 订单级，等于各行应付之和 |
| 已付 / 待退 | 支付和退款进度 | 订单级，退款明细回到行 |

税额若由业务计算，也按行保存。本专栏不展开税务规则。赠品行金额按赠品规则可以为 0，但行必须存在。

## 分摊默认算法

1. 先计算每行“单价 × 数量 − 行级优惠”，作为订单级优惠的分摊基数，不能用尚未算出的最终成交金额反推优惠。渠道已经给出行级分摊时先校验合计，避免再次分摊。
2. 行分摊优惠 = 订单级优惠 × 该行基数 / 参与行基数合计。扣除分摊优惠后得到商品成交金额，再用商品成交金额分摊运费。
3. 以整数分保存结果，按稳定行号顺序逐行计算，并把结果限制在剩余待分摊金额和本行可承担金额内；最后一行承接余数。若最后一行承接后超过行金额，向前回分剩余差额，不能形成负成交金额。
4. 金额为零的赠品不参与商品优惠比例。参与基数全部为零时，不做除法：商品优惠必须为零；若有运费，按明确的数量或指定行规则分摊并保存依据。
5. 校验行优惠不超过可优惠金额、行应付非负，以及行合计与订单金额完全一致。稳定顺序与分摊规则版本进入快照。

例如订单级运费 1.00，两行成交金额分别是 1.00 和 2.00。第一行分 0.33，第二行承接 0.67，合计仍为 1.00。对于优惠金额大、行金额很小的组合，还要覆盖尾差超过末行容量的用例。

分摊结果一旦写入订单行快照，后续退款都用这份快照。不因为后来改了促销规则而重算历史订单。

## 部分发货和部分退款

部分发货时，按“行成交金额 × 本次发货数量 / 行订购数量”分配业务发货金额，保存已分配金额并由最后一份承担尾差；取消和发货共同分配原行金额，不能各自重新四舍五入造成总额变化。运费学习默认随第一张发货单记录一次；若按包裹拆运费，在拆单时确定分摊并校验合计。这些是业务凭据金额，财务收入确认另按财务规则执行。

部分退款不能超过该来源行的批准金额和原支付可退余额，两层额度均扣除已成功及处理中退款。已发货退货的可申请数量要扣除已退与在途申请；未发货取消退款根据确认取消量及其分摊金额计算，不受“已发数量”限制。仅退款不回补库存；退货退款要等质检结果，再决定回补哪种库存。

退款优先退到原支付流水。一笔订单多次支付时，按支付流水分别记录可退余额。

## 不同业务模式的价格

直营行保存渠道成交价。经销和采销行保存合同价。一件代发除了向消费者收取的成交价，还要保存向供应商结算的供货价。供货价不参与消费者退款分摊，参与供应商对账。

改价只允许发生在未放行或未锁定之前。已锁定后改价，要重新校验应付、已付和信用冻结是否仍然匹配。已出库的价格不能改，差价走售后。
