# 金额与分摊

> 本页给出一套可学习的金额模型。优惠分摊有多种算法，这里采用「按商品金额比例分摊，尾差进最后一行」作为默认，便于部分发货和部分退款。

订单如果只有一个总价，部分发货和部分退款就无法解释每一行该确认多少钱。金额要在接单时分到订单行，并写进快照。

## 金额组成

| 金额 | 含义 | 放在哪 |
| --- | --- | --- |
| 商品标价 | 下单时的单价乘数量 | 订单行 |
| 商品优惠 | 单品折扣、满减分摊、优惠券分摊 | 订单行 |
| 商品成交金额 | 标价减去商品优惠 | 订单行，后面分摊的基数 |
| 运费 | 向客户收取的运费 | 先有订单级，再分摊到行 |
| 运费优惠 | 免邮、运费券 | 随运费分摊 |
| 应付 | 成交金额 + 实收运费 | 订单级，等于各行应付之和 |
| 已付 / 待退 | 支付和退款进度 | 订单级，退款明细回到行 |

税额若由业务计算，也按行保存。本专栏不展开税务规则。赠品行金额按赠品规则可以为 0，但行必须存在。

## 分摊默认算法

1. 只对有商品成交金额的行分摊订单级优惠和运费。金额为 0 的赠品行不参与比例，除非规则指定赠品也分摊运费。
2. 某一行分到的金额 = 订单级金额 × 该行商品成交金额 / 全部参与行的商品成交金额。
3. 计算过程保留到分，四舍五入。
4. 最后一行承担尾差，使各行之和等于订单级金额。

例如订单级运费 1.00，两行成交金额分别是 1.00 和 2.00。第一行分 0.33，第二行分 0.67。不能两行都进位成 0.33 和 0.67 以外的组合导致总和变成 0.99 或 1.01。

分摊结果一旦写入订单行快照，后续退款都用这份快照。不因为后来改了促销规则而重算历史订单。

## 部分发货和部分退款

部分发货时，本次可确认的商品金额 = 行成交金额 × 本次发货数量 / 行订购数量。运费是否在第一次发货就全部确认，需要规则：学习默认是运费随第一张发货单确认，避免同一笔运费确认多次。若业务要求按包裹拆运费，就在拆单时把运费分到履约任务，并保证合计不变。

部分退款不能超过该行尚未退过的可退金额。可退数量同样不能超过已发数量减去已退数量。仅退款不回补库存；退货退款要等质检结果，再决定回补哪种库存。

退款优先退到原支付流水。一笔订单多次支付时，按支付流水分别记录可退余额。

## 不同业务模式的价格

直营行保存渠道成交价。经销和采销行保存合同价。一件代发除了向消费者收取的成交价，还要保存向供应商结算的供货价。供货价不参与消费者退款分摊，参与供应商对账。

改价只允许发生在未放行或未锁定之前。已锁定后改价，要重新校验应付、已付和信用冻结是否仍然匹配。已出库的价格不能改，差价走售后。

## 待确认问题

- 订单级优惠按金额比例、按数量，还是由渠道已经分摊好？
- 运费在整单、第一次发货还是每个包裹上确认？
- 退款是否退运费？部分退货退多少运费？
- 经销订单的信用冻结用合同价还是折后价？
