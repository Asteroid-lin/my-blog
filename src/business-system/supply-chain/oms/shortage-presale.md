# 缺货与预售

> 本页给出缺货和预售的通用处理。默认不超卖。是否允许部分发货、等补货或卖在途，由规则打开，不作为隐式行为。

可售不足不是一种状态名能说清的。要先区分：现货不够、别的仓有货、在途将到、还是根本没有补货。

## 现货不足时的去向

寻仓并且尝试锁定之后，按下面的顺序处理。前一步成功就不再往下走。

```text
选定仓锁定成功 → 正常履约
锁定失败 → 还有下一个合格仓 → 换仓再锁
没有合格仓 → 查看缺货策略
```

| 策略 | 行为 | 默认 |
| --- | --- | --- |
| 整单挂起 | 一行不够则整单不发，等待补货或人工取消 | 未声明策略时使用 |
| 部分发货 | 有货的行先发，缺货行继续等待 | 必须规则明确允许 |
| 等补货 | 不取消，入库后再分配 | 要有等待期限 |
| 取消缺货部分 | 释放相关占用，已支付则退对应金额 | 需回传渠道 |
| 超卖 | 先承诺，允许可售为负 | 本专栏默认关闭 |

允许部分发货只是策略，实际出现出库数量后订单才展示部分发货。已发数量和未发数量都保留。未发部分不占用已经失败的那次锁定。若策略是等补货，对未发数量保留待分配需求，不假装已经锁定。整单挂起时还要决定已成功占用部分是限时保留还是在可撤销条件下释放，并设责任人与核查期限。

等补货要有截止时间。到期仍无货，就转为取消或继续挂起，并通知责任人。不能无限等待。

## 预售

预售卖的是尚未入库的预期数量，和现货可售分开记账。

| 数量 | 能否被普通订单占用 | 能否被预售订单占用 |
| --- | --- | --- |
| 现货可售 | 能 | 规则允许时才能，避免预售抢走现货 |
| 预售可售（在途预期） | 不能 | 能 |
| 残次等不可售 | 不能 | 不能 |

学习默认：普通订单只锁现货；预售订单只锁预售可售。这样现货订单不会被预售占满，预售也不会把在途当成已经在库。

预售先保存需求和供应承诺，不下发 WMS。入库回传并质检可售后，根据实际可用仓进行寻仓；在一个事务内占用现货并结清对应预售承诺，再生成可下发任务。不能先无条件释放预售承诺、再尝试占用现货，也不能转了现货后仍让原承诺重复转入。少到时只转换实际能分配的部分，剩余进入缺货策略。

优先级要事先写明，例如按下单时间。没有优先级时，不得随意挑单分配。

## 供应批次、尾款和延期

预售承诺至少绑定供应批次、SKU、数量、预计可用日、目标节点范围和版本。预计采购 100 件不是自动可售 100 件，需要供应方确认、扣除已承诺及风险预留后，由预售规则给出上限。采购或调拨协同见[补货、采购协同与调拨](./replenishment-transfer.md)。

| 事件 | 业务处理 |
| --- | --- |
| 首付款成功 | 保存真实支付记录，按政策占用预售额度；尚未满足发货条件 |
| 尾款待付 | 保存待付金额和截止时间，是否继续保留供应承诺由规则决定 |
| 尾款付清但货未到 | 资金已满足，继续等待可售入库，不向 WMS 下发无货任务 |
| 到货但尾款未付 | 不发货；是否限时转为现货预留需单独批准规则 |
| 少到、延期或供应取消 | 找到受影响订单，更新预计、挂起或申请改约/取消 |
| 客户取消 | 释放可撤销预售/现货占用，已收款按批准政策另行退款 |
| 关单后尾款迟到 | 保存资金事实，不重新发货，进入退款或人工处置 |

首付款、尾款分别记支付流水，可退范围取决于批准政策与实际收款，不在 OMS 中凭“预售”二字推断退款规则。第一版未实现该模式时，应拒绝或挂起预售订单，不能作为已全额支付的现货单导入。

原始承诺日期与最新预计分开保存，客户同意改约单独记录。延期通知发送成功不能替代客户同意，见[交期承诺与履约规则](./delivery-promise.md)。

## 和锁定时点的关系

缺货判断发生在选定仓库并尝试锁定的那一刻。锁定前的库存展示只作参考。并发下两笔订单同时看到最后一件货，只有锁定成功的那一笔可以继续，另一笔走缺货策略。

单仓场景如果在放行时就锁定，缺货会更早暴露在审单或放行阶段，处理策略仍然用上表，不另做一套。

## 补货之后

入库、调拨入库或退货质检为可售时，触发一次再分配：只处理状态为待分配、且策略允许等补货或预售转现货的订单行。再分配使用和普通寻仓相同的锁定规则。一次入库不要手工把数量改到订单上而不写流水。

调拨本身不是销售订单。它改变仓库之间的在途和现货，可能让原来缺货的订单重新获得可售。

## 场景验收

预售承诺 10 件，只入库并质检良品 6 件：最多转现货 6，剩余 4 保留待处理；重复入库事件不能再转 6。尾款未满足时不下发，客户取消和入库转换并发时不能同时释放两次或保留两份占用。到货触发任务必须在崩溃恢复后仍可重新扫描待转换需求。
