# 运营工作台与权限

> 工作台服务于查单、解释、恢复和核对。以下为待实现的产品与运行设计，需与业务人员确认具体审批职责和时限。

## 页面应该支持哪些业务动作

| 页面 | 必要信息 | 允许操作及前置条件 |
| --- | --- | --- |
| 订单列表与详情 | 店铺、订单号、独立状态、金额、行数量、时间线 | 查看关联任务、包裹、取消、售后和支付 |
| 审单工作台 | 挂起原因、命中规则、资料缺口、规则版本 | 补映射后重审；强审需要权限和理由，不能绕过库存/资金约束 |
| 分配与履约 | 候选仓、选仓原因、占用量、下发结果 | 未下发重新分配；已外发先拦截，不能直接编辑仓库 |
| 取消与拦截 | 申请量、成功量、拒绝量、未知量、外部证据 | 查询拦截、处理部分取消；未知结果保持待处理 |
| 售后与退款 | 原包裹行、收货质检、批准金额、退款状态 | 审核申请、查询退款；未知退款不能用新号重复申请 |
| 库存与流水 | 库存维度、实物、占用、安全量、业务流水 | 查看占用去向、发起对账；不提供直接改可售入口 |
| 接口与任务 | 请求号、外部单号、接收/执行状态、重试时间 | 查询外部结果、重试同一任务、重放原事件 |
| 对账差异 | 两端值、取数水位、影响订单、责任人 | 领取、调查、执行修复命令、复核关闭 |
| 规则与主数据 | 映射、有效期、规则版本、变更记录 | 校验后发布；历史任务继续使用原决策快照 |

详情页沿“渠道订单 → OMS 行 → 分配 → 占用 → 出库/包裹 → 取消/售后 → 退款”展示关联。看到“失败”时应同时能看到失败阶段、是否已联系对端和下一步责任方。

## 操作权限和数据范围一起校验

| 角色 | 动作权限示例 | 数据范围示例 |
| --- | --- | --- |
| 客服 | 查询、申请取消、申请售后 | 授权店铺订单及脱敏收货信息 |
| 运营 | 审单、挂起、重分配、处理映射 | 授权组织与店铺 |
| 仓储对接 | 查履约、查回传、申请补拉 | 授权仓库的任务 |
| 财务对接 | 审核退款、查资金差异 | 授权经营主体 |
| 运维 | 查任务、重放、排查日志 | 环境及集成方范围，不默认拥有退款审批权 |
| 管理员 | 角色、组织、仓库、规则配置 | 经授权的管理范围 |

服务端每次查询和命令均校验数据范围；前端隐藏按钮只改善体验。导出、批量操作、重放、详情接口同样要校验，不能从列表有权限推断后续接口都安全。

一期退款审核与执行、重大库存冲正可采用不同人员复核。审批人、执行人和规则版本写入审计；自动退款也记录触发规则及原始业务依据。

## 防止页面上的并发误操作

变更请求携带 `expectedVersion`，版本不一致时返回当前状态，要求重新读取。按钮点击后展示业务命令号和处理中状态，重复点击复用原请求号。批量操作返回逐单结果，不因其中一笔成功就显示整批成功。

运营处理异常时可领取处理权，但领取超时不改变业务状态；另一个人接手后仍需重新核实 WMS 或退款方结果。人工领取锁不能代替数据库数量约束。

## 审计和日志分别记录

`operation_log` 至少保存操作人或系统身份、动作、对象、请求号、原因、变更摘要、审批记录、时间及结果。业务流水解释数量变化，审计解释谁为何发起，调用日志解释请求在哪失败，三者通过业务号关联。

地址、手机号和报文中的凭据不进入普通日志。工作台默认脱敏，查看原文需要单独权限并留审计；密钥不作为可查看报文字段。原始报文采用受控存储引用和保留期限。

## 指标要对应处理动作

| 指标 | 说明 | 超阈值后的动作 |
| --- | --- | --- |
| 接单到可履约时长 | 区分待映射、待支付、审单耗时 | 按阻塞原因分派责任人 |
| 未决外部命令数及最老等待时长 | 下发、拦截、退款分开统计 | 查询对端并按时限升级 |
| 库存缺口与占用不平数量 | 按货主、仓、SKU、质量定位 | 停止受影响维度新分配并对账 |
| 回调处理积压和失败率 | 接收到业务处理完成的延迟 | 查依赖、映射和业务冲突 |
| 最晚发货时间临近订单数 | 剩余未发数量不为零 | 优先处理或按规则取消 |
| 对账差异数量及存续时长 | 不把未关闭差异隐藏在成功率中 | 领取、修复、复核关闭 |

阈值来自渠道承诺、仓库作业时段和实测容量；先记录目标和告警责任人，再设置数值。避免把不存在的生产指标写成“已达到”。

## 扩展业务的运营入口

| 入口 | 责任和必须看到的信息 |
| --- | --- |
| 渠道同步/导入 | 运营查看检查点、未转换来源单和冲突；逐行修复后重放 |
| 缺货和供应承诺 | 供应对接人查看等待订单、供应批次、预计日期与少到量 |
| 交期风险 | 运营看到原承诺、最新预计、候选替代与客户改约结果 |
| 直发/门店/自提 | 节点对接人查看接受/拒绝/未知量、自提待领取及超期量 |
| 换货补发 | 客服分别查看退旧、新发、差价和未收尾事项 |
| 物流异常及索赔 | 客服跟进客户处置，物流对接跟进实物，财务跟进赔付 |
| 账单和票据 | 财务对接人查看来源明细、跨期差异、开票及调整状态 |
| 批次质量追溯 | 质量人员查看冻结范围、受影响包裹、召回任务和追溯缺口 |

这些入口按[业务覆盖清单](./business-coverage.md)中的启用范围建设，并沿用动作权限、数据范围与审计。不可用新增按钮直接修改库存、核销或财务结果绕过业务命令。

## 试运行和回退

上线前保存库存初始化水位、未完成订单迁移清单和接口切换时间。先放一个店铺或仓库，核对接单、占用、出库、退款全链路后逐步扩展。

出现故障时可以暂停新接单/新分配/新下发，继续接收已执行任务的事实回传并提供查询。回退应用前确认数据结构兼容，不能用恢复旧数据库快照抹掉已发货和已退款事实。对已外发命令必须逐笔查询或对账后收敛。
