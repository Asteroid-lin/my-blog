# 支付与放行

> 本页描述 OMS 如何使用支付和信用结果决定订单能不能履约。支付渠道里的扣款、清分和会计处理以支付系统和财务系统为准。

放行表示「这笔订单允许开始占库存和发货」。零售看支付，经销和采销看信用或预付款，货到付款看审单和承运规则。模式说明见[业务模式](./business-mode.md)。

## 支付在链路中的位置

```text
接单并完成主数据映射 → 审单
  → 零售：等待支付成功
  → 经销 / 采销：校验信用或预付款
  → 货到付款：按规则先放行
  → 进入寻仓与锁定
```

未放行的订单不锁定库存，也不下发 WMS。避免支付失败的订单占着可售。

## 在线支付

| 事件 | OMS 怎么处理 |
| --- | --- |
| 待支付 | 订单停在待支付，记录应付金额和超时时间 |
| 支付成功 | 按支付流水号幂等。第一次成功才放行；重复回调只返回已处理 |
| 部分支付 | 默认不放行。只有规则写明允许多次付清，才在付清时放行 |
| 支付失败 | 保持待支付，等待用户重试，直到超时 |
| 超时未支付 | 关闭订单。若之前有预锁，必须先释放 |
| 支付成功但订单已关闭 | 不重新发货。转人工退款，避免关单后又发出去 |

支付流水号是幂等键。同一流水重复通知不能把订单推进两次，也不能生成两笔应收。

金额以订单应付为准。渠道优惠已经体现在成交价里时，OMS 保存优惠前金额、优惠和应付，避免退款时算错。分摊方式见[金额与分摊](./pricing.md)。

## 货到付款

货到付款订单审单通过后可以履约，因为钱还没到。履约任务要带明代收金额。承运商回传代收成功，才把支付状态改为已支付。拒收则不产生收款，货按退货入库处理。

代收金额应等于仍需向收货人收取的应付。中途改金额必须发生在揽收前，并同步给承运商。

## 信用与预付款

经销、采销在放行时读取财务给出的可用额度：

```text
可用额度充足 → 冻结本次订单金额 → 允许寻仓
发货时 → 按实际发货金额形成应收，并调整冻结
未发货取消 → 释放冻结
已发货退货 → 等财务确认退货金额后冲减应收
```

OMS 不自己计算信用政策。它保存财务返回的审核结果、冻结金额和有效期。调用超时不能当成审核通过。

预付款客户用账户余额代替信用。余额不足则挂起，不部分占用后强行发货，除非规则明确允许分批付款、分批发货。

## 发货前退款

已支付、尚未出库的取消：先拦截履约并释放库存，再按原支付流水发起退款。退款请求同样要幂等。

已经出库的不能走这条退款。应先建售后单，按[售后中心](./after-sales.md)的退货或仅退款规则处理。仅退款必须单独审核，确认不需要退货。

## 和财务的边界

OMS 记录业务上的应付、已付、待退和代收。财务记录预收、应收、实收和退款凭证。两边用订单号、订单行、支付流水和售后单对账。接口发送成功只说明消息到了，不说明账已经一致。
