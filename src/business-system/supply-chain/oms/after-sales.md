# 售后中心

> 售后规则需结合渠道承诺、仓库质检和财务退款条件确认。本页先梳理单据关系与逆向链路，不预设所有售后都要退货入库。

## 业务目的与类型

售后中心处理交易发生后的退款、退货、换货、补发、拒收和报修，保证客户诉求与订单、履约、库存和财务结果可追溯。不同类型的实物流和资金流并不相同：

| 类型 | 实物流 | 资金或订单影响 |
| --- | --- | --- |
| 仅退款 | 通常没有退回实物 | 核实可退金额与支付/结算状态 |
| 退货退款 | 客户寄回，仓库收货并质检 | 按审核与收货规则退款 |
| 换货 | 退回旧件并安排新件发货，次序依规则而定 | 核对差价、库存和新履约任务 |
| 补发 | 对漏发、破损等重新履约 | 关联原订单及补发原因，防止重复发货 |
| 拒收 | 包裹退回或由物流处理 | 核实物流结果后处理退款和库存 |
| 报修 | 商品留在客户处，或寄回维修点；可能另发配件 | 保修期内通常不退货款；保外可以另收维修费 |

## 退货流程（示意）

```text
客户/渠道申请 → 关联原订单行与已发数量 → 校验可售后数量
  → 审核并生成售后单 → 指定退货地址或逆向方式
  → WMS 收货与质检 → 判定良品、残次品或不入库
  → 库存处理与退款/换货 → 回传渠道并关闭售后单
```

售后单应记录原订单、订单行、发货单或包裹、申请数量、已处理数量、原因、审核结果和每个外部业务单号。数量上限需扣除已退、已换和在途申请，避免重复退款或超过实际发货数量。可退金额按订单行上已经分摊的成交金额和运费计算，见[金额与分摊](./pricing.md)。退哪一个包裹，以[包裹、运单与回传](./package-logistics.md)上的行数量为准。

不同诉求要分别占用可处理额度：同一件在途退货不能再次申请退货，已成功退款或处理中退款占用资金额度；换货后的新商品再售后应追溯新履约来源，不能永久扣掉原商品的一次换货量就拒绝后续所有诉求。第一版先实现取消退款、退货退款和经审核的仅退款，换货与维修另行设计。

换货与补发的退旧发新、差价、售后独立需求和二次售后已单独展开为[换货、补发与售后衍生单](./exchange-reship.md)。物流丢损与拒收进入[物流异常、拒收与赔付协同](./logistics-exception.md)，实际退货仍需收货质检。

## 报修

报修处理的是「货已经在客户手里，但不好用」。它不把原订单改成退货，也不因为受理了报修就增加可售库存。公众号、平台和客服外部渠道是三条受理途径，汇合规则见[报修入口](./repair-intake.md)。

```text
客户或渠道报修 → 按订单行、序列号或批次找到原商品
  → 判断是否在保修期内、是否重复报修
  → 生成报修单 → 选择上门、寄修或只发配件
  → 维修点回传进度 → 客户确认可用，或转退换
  → 关闭报修单
```

报修单要挂回原订单行和包裹，并记下故障现象、序列号、购买或签收时间、保修截止时间、处理方式和每个外部单号。同一商品已有未关闭的报修单时，再次提交应返回原单，不能并列两张在修单。

三种处理不要混成一种库存动作：

| 处理方式 | 货在哪 | 库存怎么记 |
| --- | --- | --- |
| 上门维修 | 商品留在客户处 | 不入库。若更换配件，只扣配件库存 |
| 寄修 | 客户寄到维修点，修好再寄回 | 记维修在途，不进可售。修完寄回也不增加可售 |
| 无法修复 | 转入退货或换货 | 关闭报修原因，再走退换流程，避免又退款又算在修 |

保修期从发货或签收起算，以规则约定的那个时点为准，不用「现在还能退货」代替「现在还能免费修」。过保后可以转成收费维修，收费要单独形成应收，不从原订单已付金额里扣。

上门和寄修的执行方可能是自有网点、第三方服务商或供应商。OMS 记录派给谁、对方是否接单、超时未修如何升级。执行方的维修工艺和配件核销以对方回传为准，OMS 不因为派单成功就当成已经修好。

## 售后与库存、财务的边界

退货签收不等于可售库存增加：仓库还需收货与质检，残次品可能进入不可售库存。退款审核也不等于资金已退；支付渠道或财务系统的成功结果应独立回传。补发会产生新的履约任务与库存占用，仍要关联原售后单。取消未发货订单与已发货退货属于不同链路，详见[订单中心](./order-center.md)。

建表时对退货明细、原支付退款额度和来源行批准金额分别做约束，详见[数据模型与约束](./data-design.md)；退款超时仍保留额度，按原退款号查询，详见[一致性与恢复设计](./consistency-recovery.md)。

## 异常与待确认问题

重复申请、渠道取消售后、物流丢件、部分收货、质检差异和退款失败都需要记录当前状态与下一责任方，支持按业务单号重试和对账。

- 各业务模式的售后入口、审核方、退货期限与可退数量口径是什么？
- 退款是在审核通过、WMS 签收还是质检完成后发起？运费和差价如何处理？
- 换货与补发产生何种新单据？旧货未到时能否先发新货？
- 拒收与物流退回如何判定，何时释放或回补可售库存？
- 哪些商品支持报修？保修期从发货还是签收起算？过保后是否允许收费维修？
- 上门、寄修和发配件分别由谁执行？配件从哪个库存扣减？
- 报修失败后转退货或换货时，原报修单和退换单如何关联，会不会重复退款？
