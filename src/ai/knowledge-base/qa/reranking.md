# 重排序与上下文组织

本模块从候选片段中选出最能支持当前问题的证据，组织为模型可用的上下文。排序优先级不能替代文档权限、适用条件和来源权威性。所属场景：[知识检索问答](./README.md)。

## 业务目标与输入输出

输入包括原问题、检索问题、候选片段、来源位置、文档版本和授权范围；输出是具有引用标识、顺序、适用范围和完整条件的证据集合。业务目标是减少无关内容，保留回答所需的依据，而不是把候选全部塞入模型。

## 正常流程

1. 复核候选当前仍有权限、未停用且版本有效，移除不能确认的内容。
2. 按问题与片段关系进行重排序，保留排序结果和策略版本。
3. 去除高度重复的内容，同时保留独立来源及不同适用条件。
4. 检查问题包含的各个要点是否有证据覆盖，避免一个高分片段垄断全部上下文。
5. 需要时补充父章节、相邻片段、表头或备注，并对补充内容重复授权与版本检查。
6. 预留回答长度、系统规则和问题的预算，再分配证据上下文。
7. 为选中内容分配稳定引用标识，建立“引用 → 文档版本 → 原文位置”映射。
8. 记录证据不足、来源冲突和裁剪信息，交给答案生成。

如果排序服务不可用，可按已批准的候选排序策略降级；前提是权限已验证并且证据质量仍达到回答门槛。否则返回暂时无法回答或仅展示获准访问的检索结果。

## 证据选择规则

| 情况 | 处理原则 |
| --- | --- |
| 多个片段重复同一条款 | 合并冗余，保留可追溯来源 |
| 同制度的新旧版本 | 使用符合当前发布和业务生效期的版本 |
| 不同地区或产品的规则 | 保留条件，不能混成一条统一规则 |
| 正式制度与个人笔记冲突 | 按经确认的来源优先级处理 |
| 两个同级有效来源冲突 | 显示冲突并要求确认，不由模型自行选一方 |
| 问题有多个子问题 | 检查逐项证据覆盖，允许部分回答 |

“更新时间更近”不必然等于“业务优先级更高”。应区分系统修改时间、业务生效时间和制度发布级别。

## 上下文预算与裁剪

预算需要覆盖系统规则、问题、必要历史、证据和预期回答。按实际模型的 token 计量评估，不能只按字符数量估算后认为一定可用。

先移除无关和重复证据，再压缩低优先级说明。金额单位、例外、否定词和适用条件不可为了省长度随意裁掉。长表格可以按相关行选取，但要保留表头和备注；条款拆分后若失去条件，应整条保留或放弃使用。

对上下文的摘要属于新派生产物，可能改变原意。需要保留原片段引用并核对事实，不能把摘要当作新的权威来源。

## 来源信息与数据边界

每项证据至少携带引用标识、文档身份、标题、内容版本、来源位置和必要适用条件。服务凭据、内部存储地址和无关用户信息不进入模型上下文。

检索内容可能包含恶意指令。组织上下文时应把文档材料与系统规则明确分开，文档中的操作性文字仅是待分析内容；模型不能据此扩大检索范围或执行外部动作。相关风险概念参考 [OWASP 提示注入防护说明](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)，本页流程为项目设计基线。

## 业务示例

用户问“异地寄修收费吗，运费由谁付”。最高分片段只有维修费用，另一个稍低分片段说明运费承担。若只取最高分，回答会漏掉一半问题。应保留两类证据，并说明维修费还受保修状态与损坏原因影响。

## 异常与验收

| 场景 | 预期 |
| --- | --- |
| 前十条均来自同一重复段落 | 去重后补充其他相关证据 |
| 相关片段末尾有免责条件 | 条件不会因裁剪丢失 |
| 父章节包含更严格权限内容 | 不因补上下文而越权 |
| 两份有效制度结论不同 | 保留冲突标记，不暗中删除一方 |
| 排序服务超时 | 按明确政策降级或返回失败 |
| 文档要求“忽略系统规则” | 不改变系统授权与执行边界 |

## 实施决策

确定来源权威等级、版本适用规则、上下文预算、排序服务降级方式及允许自动回答的最小证据要求。
