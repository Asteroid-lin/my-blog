# 问题理解与检索范围

本模块明确用户在问什么，以及本次允许查哪些知识。问题改写可以帮助检索，访问范围必须由可信身份与授权规则决定。所属场景：[知识检索问答](./README.md)。

## 业务目标与参与角色

提问用户选择知识库、文档或业务分类，系统结合当前问题和允许使用的会话上下文生成检索请求。知识库管理员维护知识分类与适用范围，业务人员确认术语和问题歧义。

例如用户先问“寄修运费由谁承担”，接着问“超过保修期呢”，系统可以补全为“超过保修期的寄修运费由谁承担”。若历史同时讨论多个产品，应先澄清产品或给出分支，不能任意选一个。

## 输入与输出

| 输入 | 使用规则 |
| --- | --- |
| 当前问题 | 保留原文，用于解释改写和评估 |
| 用户与租户 | 由可信身份确定 |
| 知识库选择 | 必填场景必须明确选择，服务端验证授权 |
| 文档、分类与标签 | 只能缩小已授权范围 |
| 会话上下文 | 绑定用户、租户和会话范围，重新核对可用性 |
| 业务时间与对象 | 区分产品、地区、生效期等适用条件 |

输出包括原问题、检索问题、必要子问题、知识库集合、授权过滤条件、业务过滤条件和追踪编号。范围为空时明确返回无可访问知识或要求补全，不能自动搜索全租户或默认知识库。

## 正常流程

1. 校验用户身份、请求长度、会话归属和目标知识库状态。
2. 计算本次允许访问的知识库与文档范围。
3. 保留原问题，识别产品编号、日期、区域、对象和用户目标。
4. 选择相关且当前仍允许使用的历史轮次，处理“这个”“刚才”“它”等指代。
5. 需要时改写检索表达，保留原有时间、否定、数量和限制条件。
6. 遇到影响答案的歧义时提出澄清；多个独立问题可拆分检索。
7. 固定本轮范围和策略版本，进入召回；把解释性记录保存到受控追踪中。

改写失败时可在原问题已明确且范围安全的条件下使用原问题检索，并记录降级。不能把授权校验失败当作可降级问题。

## 范围组合规则

本次候选范围为“用户授权范围 ∩ 所选知识库 ∩ 文档有效状态 ∩ 业务筛选条件”。用户选择“全部”也只能表示全部已授权内容。

| 情况 | 业务处理 |
| --- | --- |
| 未选必填知识库 | 提示选择，不默默采用其他库 |
| 指定不存在或无权访问的文档 | 返回统一的不可访问结果，避免暴露文档存在性 |
| 多库联合查询 | 逐库授权，按产品规则决定部分可用还是整体拒绝 |
| 用户切换知识库 | 重新计算范围，历史上下文不自动扩大到旧范围 |
| 用户询问实时订单状态 | 指出知识文档的时效边界；实时查询需另接经授权的业务接口 |
| 用户要求修改订单、执行退款 | 进入独立业务操作流程，知识问答本身不执行 |

## 多轮会话与历史知识

会话 UUID 只标识会话，不能代替用户身份与租户边界。历史检索片段、摘要和助手回答都可能包含后来被撤权的知识，应建立来源关联并在继续使用时重新检查。

如果不能判断历史摘要是否仍允许使用，应舍弃受影响上下文并重新检索。用户自己提供的文本与系统曾检索的受限内容需要有可区分的来源记录。

## 异常与用户反馈

问题过长时说明可接受范围；无上下文支撑的指代要求澄清；模型改写增加原问题没有的事实时回退原问题；没有任何授权知识时说明无法在当前范围查询，不说“公司没有这项制度”。

## 验收场景

| 输入 | 预期 |
| --- | --- |
| “超过保修期呢”且前文对象明确 | 补全指代，保留过保条件 |
| 问题中包含产品编号和否定词 | 改写不丢失编号或反转含义 |
| 切换到另一知识库 | 当前检索和历史上下文都受新范围约束 |
| 他人会话编号 | 无法读取或继续会话 |
| 授权失效后继续追问 | 不复用失效来源的历史内容 |
| 问实时状态但只有历史制度 | 明确能力与时效边界，不编造业务结果 |

## 实施决策

确定知识库是否单选、历史轮次保留范围、何时澄清、是否允许跨库联合查询，以及哪些实时问题需要路由到独立业务系统。
