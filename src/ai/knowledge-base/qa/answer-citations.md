# 答案生成与来源引用

答案生成把经过筛选的证据转为面向用户的说明，并让用户能够核对结论来源。业务目标是回答有依据、条件讲清楚、未知能说明，而不是保证每个问题都得到肯定答案。所属场景：[知识检索问答](./README.md)。

## 输出约定

| 组成 | 要求 |
| --- | --- |
| 直接结论 | 回答用户当前问题，不绕过关键条件 |
| 适用范围 | 标明产品、地区、对象、时间或制度版本 |
| 依据与引用 | 关键业务结论能对应有效证据 |
| 操作说明 | 来自文档，保持步骤与注意条件完整 |
| 信息缺口 | 区分无资料、权限不足、证据冲突和系统故障 |
| 后续入口 | 可查看原文、补充问题或转业务负责人确认 |

模型产生的自然语言不是业务系统执行结果。回答“可以申请退款”不代表已经退款，涉及修改数据的动作必须走独立授权和业务流程。

## 正常流程

1. 接收问题、上下文、证据清单、适用条件和证据不足标记。
2. 根据回答规则组织提示，将资料内容和系统约束分离。
3. 生成答案，要求证据支持关键结论，不能用模型常识补写公司制度细节。
4. 检查引用标识是否真实存在，检查关键结论是否与引用证据一致。
5. 输出前核对文档是否被停用、权限是否发生变化；必要时重新检索或终止返回。
6. 保存本轮问题、策略版本、答案、引用映射和执行状态，按保留政策处理正文。
7. 接收用户反馈，允许定位到本轮证据与版本。

引用标识有效仅证明引用存在，不能证明引用支持结论。金额、期限、资格条件等应做有针对性的核对，并纳入离线评估。

## 无答案与部分回答

| 情况 | 用户可理解的反馈 |
| --- | --- |
| 当前授权范围没有支持证据 | “当前所选知识中未找到足够依据” |
| 缺少产品或业务条件 | 请求补充条件，或列出有依据的分支 |
| 部分问题有证据 | 先回答可确认部分，明确剩余缺口 |
| 同级有效来源冲突 | 展示冲突点及来源，转负责人确认 |
| 资料无法判断实时业务状态 | 指向可查询实时状态的业务入口 |
| 检索或模型服务失败 | 明确本次未完成，允许稍后重试 |

不要说“没有搜到，所以不存在这项政策”。也不能把权限拒绝描述为已确认某份秘密文件存在。

## 引用与原文访问

引用至少能定位文档、内容版本和页码、章节或片段位置。点击引用时重新鉴权，通过受控入口打开原文；不把长期有效的私有存储地址直接暴露给前端。

历史回答应保留当时依据的版本。旧版本是否仍可打开由留存与访问规则决定；无权访问时提示不可用，不静默跳转到新版本后让用户误以为当时依据相同。

文档标题、来源描述和引用链接也可能含受限信息，权限处理不能只隐藏正文。

## 流式回答与状态

建议区分生成中、完成、中断和失败。只有明确完成的回答才计入完整成功。网络断开后重试时复用请求追踪关系，但新生成的内容可能不同，应标记为重试版本。

高敏感知识可在完整检查后再发送答案。允许流式输出时，应按策略检查访问变化并及时停止；已经发送给用户的内容无法依靠撤权自动收回，因此不能承诺撤权能消除所有历史披露。

## 业务示例

依据写着“保修期内且非人为损坏免收维修费；寄送运费由客户承担”。正确回答应同时保留“保修期内”“非人为损坏”和“运费另计”。仅回答“寄修免费”即使附上真实引用，也不符合业务要求。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 有明确证据 | 结论、条件、引用对应 |
| 模型生成不存在的引用编号 | 被拦截、修正或转为未完成回答 |
| 没有证据 | 不编造金额、期限或企业规定 |
| 文档在生成期间被停用 | 返回前检查能阻断；流式场景按明确政策处理 |
| 点击他人转发的引用链接 | 重新鉴权，不能绕过文档权限 |
| 流式连接中断 | 状态为中断，不能冒充完整成功 |

## 实施决策

确认是否流式输出、敏感场景是否缓冲、引用展示方式、答案留存期限、反馈入口，以及哪些问题必须由业务人员确认。
