# 租户识别与用户身份

本模块确认“谁在操作、代表哪个租户、通过什么入口执行”。身份确定后，知识库和文档授权才能成立。所属场景：[多租户与权限隔离](./README.md)。

## 业务对象与角色

租户是数据归属与配置边界，用户是操作主体，成员关系描述用户在某租户中的资格，角色描述可申请的操作能力。一个用户可以加入多个租户，但每次请求必须明确当前执行租户。

服务身份用于同步、索引和对账等后台任务。服务身份与人工用户分别审计，不能把所有任务都记为“管理员”而无法追踪来源。

## 身份上下文

| 信息 | 业务用途 |
| --- | --- |
| 用户或服务主体 | 标识实际执行者 |
| 当前租户 | 限定资源与配置范围 |
| 身份来源 | 登录会话、验证过的令牌或受控任务身份 |
| 成员与角色修订 | 支持权限变化后的重新判断 |
| 请求与会话编号 | 串联操作，不替代身份凭证 |
| 代理发起者 | 后台代办时记录原操作人及授权关系 |

前端可以提出租户切换意图，但服务端必须验证成员关系，再建立新的可信上下文。请求体、URL、知识库编号或会话 UUID 都不能直接充当租户授权依据。

## 交互请求流程

1. 验证身份凭证的真实性、有效期和所适用服务。
2. 确认用户仍在当前租户中，租户与账号均处于允许使用状态。
3. 建立本次可信身份上下文，加载必要角色与授权修订。
4. 对目标资源执行租户归属和操作权限校验。
5. 将身份上下文传递到业务查询、缓存、后台任务和审计。
6. 操作完成记录执行主体、租户、资源、动作和结果。

角色只是授权输入。具有“知识维护员”角色并不代表可以管理所有知识库，需要继续判断其资源范围。

## 后台任务流程

后台任务保存租户、服务身份、来源配置、受理时的发起者和任务编号。执行时重新校验服务身份与配置状态，再按任务范围访问资源。

人工提交任务后退出登录，不一定意味着任务取消；其行为由受理规则决定。但用户离职、租户停用、来源撤权等变化可能使任务不再具备执行条件，应在执行和发布阶段检查，不能永久沿用受理时的允许结论。

异步执行完成后清理线程或请求上下文，避免下一个任务错误继承上一个租户。调度器遍历多个租户时，每次切换必须独立建立上下文。

## 多租户切换与会话

| 场景 | 处理 |
| --- | --- |
| 用户从租户 A 切换到 B | 更新可信上下文，重新加载知识库与权限 |
| A 的会话链接在 B 下打开 | 拒绝或提示切回拥有权限的租户 |
| A 的文档编号提交到 B | 按资源归属拒绝 |
| 用户被移出某租户 | 后续请求与长任务复核失败 |
| 租户停用 | 停止新请求及相关任务发布，保留受控恢复入口 |
| 管理员跨租户协助 | 使用显式授权与审计入口，不能默认继承全量正文权限 |

缓存、对象存储引用、消息和业务唯一键都需具备租户维度或等效隔离能力。仅页面菜单过滤不能证明隔离成立。

## 异常与恢复

身份过期需要重新登录或刷新有效身份；无成员关系直接拒绝；身份服务不可用时不建立“默认租户”继续运行。后台任务缺少租户信息应进入人工核对，不能根据文档编号猜测归属。

身份修复后可以重新执行安全的查询。写操作先查原请求结果，避免重新认证后重复提交已经完成的业务动作。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 修改请求中的租户编号 | 不改变已认证身份可访问的租户 |
| 使用他人的会话编号 | 无法读取历史问题、答案或引用 |
| 同一用户加入两个租户 | 只使用当前租户允许的资源 |
| 连续执行不同租户任务 | 不发生上下文、日志或缓存串用 |
| 用户被移出租户 | 新请求被拒绝，任务按策略重新校验 |
| 身份服务异常 | 明确失败，不自动进入公共或默认租户 |

## 实施决策

确定租户切换方式、身份有效期、组织成员更新频率、服务身份授权范围、跨租户运维入口，以及账号停用对已受理任务的处理政策。
