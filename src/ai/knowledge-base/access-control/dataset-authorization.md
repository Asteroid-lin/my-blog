# 知识库授权与路由

本模块决定用户可以对哪个知识库执行什么操作，并把获准请求映射到正确的处理服务。授权是业务判断，路由是经过授权后的执行选择。所属场景：[多租户与权限隔离](./README.md)。

## 授权对象与操作

| 操作 | 能力范围 |
| --- | --- |
| 阅读与问答 | 检索获准文档、阅读回答与引用 |
| 新增文档 | 上传或提交新内容 |
| 维护文档 | 更新、停用或删除指定范围文档 |
| 发布审核 | 审核并发布知识版本 |
| 管理授权 | 调整知识库成员与权限 |
| 配置同步 | 维护来源连接、触发同步与处理异常 |
| 查看审计 | 查阅规定范围的操作记录 |

这些能力可以通过角色组合，但需要分别定义。能管理知识库配置不必然能阅读全部正文，能上传也不必然能删除其他人的文档。

## 授权流程

1. 从可信上下文获取租户和主体。
2. 校验所选知识库存在、属于当前租户且状态允许操作。
3. 计算角色、成员、资源授权以及显式限制。
4. 校验当前动作，得到允许或拒绝及可审计的原因。
5. 读取租户维护的目标服务映射，确认路由配置完整可用。
6. 以服务端受控凭据执行请求，并在文档层继续缩小范围。
7. 保存本次授权修订、目标知识库和结果，支持问题追踪。

如果接口要求明确选择知识库，则缺失选择必须返回校验错误。若业务配置固定目标知识库，则使用经校验的配置值；前端提供的额外目标不得绕过这一映射。

## 路由配置与数据边界

| 信息 | 规则 |
| --- | --- |
| 业务知识库标识 | 对外表达用户选择的资源 |
| 目标服务与数据集映射 | 服务端维护，必须属于允许租户范围 |
| 模型与检索策略 | 按知识库配置或经批准的请求选项使用 |
| 服务凭据引用 | 从部署环境或受控凭据服务读取 |
| 配置修订与有效状态 | 支持发布、回退和运行审计 |

第三方平台的数据集编号不是完整授权凭证。知道编号的人仍需经过本系统授权；第三方凭据也不应返回给前端。

## 多知识库查询

跨库问题需要逐库授权。建议先确定产品语义：要求所有库同时可用，还是允许只查询成功授权的部分。后一种必须明确实际搜索范围，但不能暴露未授权库的敏感信息。

同一问题涉及多个库时，仍需保留每条证据的库归属、文档版本和适用条件。不同库的角色定义、元数据或分数不能假定完全相同。

## 配置变更与故障策略

目标路由变化应先验证连接和样本，再发布新的配置修订。已运行任务记录使用的修订，结果写回时校验映射是否仍有效。跨目标迁移要处理旧文档、旧索引和引用，不只是改一个地址。

服务不可用时，仅允许切换到经过授权、数据和权限一致且预先验证的备用目标。不能为完成回答而自动改查另一租户、公共库或未知默认库。

## 业务示例

客服具有“售后公开规范”的问答权限，主管另外具有“内部赔付规则”的读取权限。客服手工提交内部库编号仍会被拒绝；系统也不能先以全权限服务账号检索内部规则，再让模型“不要泄露”。

## 页面与运营

管理页面应展示知识库所属租户、负责人、成员、可执行动作、授权有效期和最近变更。路由诊断展示目标标识和连通性，不展示服务密钥。重要授权变更形成影响清单，包含用户、服务身份和未完成任务。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 有阅读权限、无维护权限 | 可问答，不能上传或删除 |
| 目标库编号被篡改 | 无法越权，错误不泄露内部详情 |
| 必填知识库为空 | 不自动选择默认库 |
| 固定路由配置被前端覆盖 | 服务端拒绝或忽略不允许的字段 |
| 目标服务故障 | 只采用经批准的降级，权限范围不扩大 |
| 管理员更新目标映射 | 能追踪新旧配置和任务影响 |

## 实施决策

确定角色与操作矩阵、多库查询语义、固定映射或用户选择规则、配置发布方式，以及受控备用目标的验证标准。
