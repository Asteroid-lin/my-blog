# 文档权限与检索隔离

知识库可读不代表库内所有文档都可读。文档权限进一步限定组织、用户组、角色或指定成员能使用哪些内容，并约束片段、摘要、引用和原文访问。所属场景：[多租户与权限隔离](./README.md)。

## 权限模型基线

本专栏使用“上层允许范围逐级取交集”的业务基线：租户成员资格、知识库授权、文档规则、有效状态共同决定访问。文档规则不能越过租户或知识库边界扩大权限。

来源同步文档原则上不突破来源授权范围。来源权限模型无法可靠转换时，应先进入受限或待确认状态，不能把未知权限当作公开权限。

文档级过滤的通用机制可参考 [Microsoft 文档级访问控制说明](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview)。下面的授权组合与恢复流程是本专栏提出的设计选择，不意味着采用特定云产品。

## 权限数据与继承

| 数据 | 业务作用 |
| --- | --- |
| 文档、租户、知识库 | 确定资源归属 |
| 允许主体或授权标签 | 用户、用户组、组织等可访问集合 |
| 显式限制 | 收紧某些主体或动作 |
| 来源权限引用 | 支持来源权限核对 |
| 权限修订 | 判断副本和缓存是否过期 |
| 文档有效状态 | 控制停用与删除后的访问 |
| 片段归属 | 让所有片段继承正确文档权限 |

业务分类标签与权限标签要区分。调整“售后”分类不应无意改变访问范围；如果某标签参与权限判断，页面必须明确其授权影响并要求相应管理权限。

## 查询链路中的检查

1. 请求入口确认主体与知识库授权。
2. 生成检索过滤条件，限制租户、文档范围和有效状态。
3. 检索得到候选后，用当前权威权限与版本再次核对。
4. 重排序、补充上下文和摘要生成只处理已确认允许的内容。
5. 输出前按策略检查权限变化；发现撤权时重建答案或停止。
6. 用户点击引用、预览原文或下载附件时重新授权。
7. 缓存命中和历史会话复用也执行当前访问检查。

不应先向模型发送全量内容，再通过提示词限制输出。权限属于系统访问控制，不能仅靠模型遵循自然语言规则。

## 缓存、历史与派生内容

缓存应包含租户、知识范围、主体或等效授权指纹、相关权限修订和策略版本。即便缓存键隔离，读取时仍需处理已经发生的撤权。

答案、摘要和推荐问题可能包含多个文档的信息。应保存来源依赖，权限变化后整体失效或重建受影响结果；无法追踪来源时采用保守清除或停止复用。直接删除某个引用并不能保证答案正文已不含该来源的内容。

历史会话在打开、继续提问、导出或分享时重新核对。分享链接不自动授予接收者原文访问权；系统也无法收回用户已经复制到外部的内容。

## 权限更新流程

收紧权限时先更新访问权威规则或阻断清单，再刷新索引副本、缓存和派生产物。扩展权限时可等待副本准备完成后开放，避免状态不同步造成错误展示。

索引权限字段刷新失败不应阻止拒绝已撤权访问。若系统只能依靠滞后的索引字段判断，就必须在过渡期阻止受影响文档参与问答，并把限制明确列为上线前问题。

## 业务示例

“内部维修赔付表”允许售后主管阅读，普通客服只有公开规范权限。主管回答中的赔付金额不能放进全租户公共缓存。主管调岗后，旧会话中来源于赔付表的上下文不能用于新的回答，原文链接也必须重新鉴权。

## 异常与验收

| 场景 | 预期 |
| --- | --- |
| 原文受限但片段缺少权限字段 | 不发布或不召回，进入修复 |
| 索引撤权刷新延迟 | 当前访问控制仍能阻断 |
| 用户组变更后命中旧缓存 | 不能返回失效来源内容 |
| 父章节补充包含受限段落 | 重新授权，不扩大上下文 |
| 引用链接被转发 | 接收者按自身权限访问 |
| 权限服务不可用 | 停止无法确认的访问，错误可追踪 |

## 实施决策

确定文档继承方式、来源权限映射、权限标签管理、缓存失效机制、历史记录访问政策和撤权允许的传播延迟。无法满足的边界应在上线前显式处理。
