# 同步任务与内容更新

同步任务把“发现了变化”转为“目标知识已更新”的可恢复操作。任务应能回答处理谁、按什么版本处理、当前在哪一步、失败后由谁恢复。所属场景：[外部知识源同步](./README.md)。

## 任务输入与执行身份

输入是扫描生成的不可变候选快照，包含租户、来源配置修订、源文档身份、源版本、操作类型和目标知识库。执行使用租户范围内的服务身份，不能依赖某个登录用户在内存中的会话。

任务按版本保存输入。若下载时来源已变更，应按原版本读取，或重新登记新版本任务；不能悄悄改变旧任务快照后仍称其处理了旧版本。

## 操作类型与职责

| 操作 | 执行内容 | 成功条件 |
| --- | --- | --- |
| 新增 | 下载、解析、切分、索引、发布 | 目标文档和有效版本建立 |
| 内容更新 | 为已有文档构建新版本 | 新版本被条件发布 |
| 元数据更新 | 修改标题、分类、标签等 | 相关展示与检索字段已一致 |
| 权限更新 | 更新授权并刷新副本 | 当前访问规则生效，索引追踪可核对 |
| 停用或删除 | 阻止使用并清理资源 | 访问停止，清理状态另行记录 |

相同文档的内容、元数据、权限可能并发变化。任务必须说明自己更新的维度，避免一个旧内容任务把新权限或新标题覆盖回去。

## 受理与执行流程

1. 对候选做幂等登记，保证同一业务操作只有一个可追踪意图。
2. 执行器条件领取到期任务，写入执行者、尝试次数、租约到期时间和领取代次。
3. 检查配置是否仍启用、来源授权是否可用、目标是否仍有效。
4. 按快照下载内容，核对版本、长度与摘要；创建或复用目标文档映射。
5. 调用[上传入库链路](../document-ingestion/README.md)中的解析、切分和索引能力。
6. 发布前重新检查目标版本、停用状态和权限修订，拒绝过期任务发布。
7. 保存目标结果、索引映射和成功状态，再进入[结果回写](./result-reconciliation.md)。
8. 失败时记录阶段与错误类别，选择重试、等待人工、取消或被更新版本取代。

任务已接收、正在执行、目标已更新、结果已回写是不同事实。页面应分别展示，避免一个“成功”掩盖未完成阶段。

## 幂等、并发与重复消费

业务幂等键需要表达租户、来源文档、目标、操作类型和相应修订。内容摘要可以辅助比较，但不同操作即使内容相同也可能有不同业务意图。

同一文档的发布应串行或使用版本条件更新；不同文档可并发。旧任务完成时若发现已被新目标版本取代，应标记为过期或取消，不能宣告成功覆盖。

队列重复投递与执行器重启是正常恢复场景。设计目标是重复执行仍得到一致业务结果；外部接口需要幂等键、查询结果或幂等覆盖能力配合，不能只靠本地锁承诺所有外部副作用仅执行一次。

## 租约、崩溃与长任务

租约用于允许其他执行器接管失联任务。长任务需续租；租约过期后旧执行器仍可能返回，因此完成写入必须校验领取代次与任务状态。无法校验代次的外部调用，应以业务幂等和结果核对补足。

定时任务的触发租约只说明谁启动扫描，不能代替每个文档任务的执行控制。扫描进程退出、任务进程退出和结果回写失败需要独立恢复。

## 失败处理

| 失败点 | 恢复 |
| --- | --- |
| 下载前失败 | 重试下载，保留原输入版本 |
| 解析或索引部分失败 | 从检查点继续，保持当前有效版本 |
| 外部创建成功、响应超时 | 先按业务标识查询，确认不存在再创建 |
| 本地提交结果失败 | 对账外部结果后补记，不直接重复全文入库 |
| 权限失效 | 停止任务并通知配置负责人 |
| 新版本任务已发布 | 旧任务禁止发布，其残留产物进入清理 |

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 同变更被扫描和事件同时发现 | 一个业务任务或可归并的同一结果 |
| 两执行器同时领取 | 只有合法领取者可提交有效状态 |
| 旧执行器租约过期后返回 | 不能覆盖接管者结果 |
| 下载返回更高版本内容 | 版本不冒名，重新识别并登记 |
| 同步期间停用文档 | 后续处理不能将文档重新发布 |
| 目标成功但回写失败 | 不重新解析，只恢复回写 |

## 实施决策

确定任务粒度、单租户并发配额、租约与续租周期、外部幂等能力、内容操作排序策略，以及人工恢复的审计方式。
