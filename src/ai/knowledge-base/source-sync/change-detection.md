# 变更扫描与版本识别

扫描回答“自上次处理后哪些文档发生了什么变化”。它产生可靠的变更候选，不直接把一次列表结果当作同步成功。所属场景：[外部知识源同步](./README.md)。

## 业务对象与身份

来源文档身份建议由租户、来源实例、来源空间和源文档编号共同确定。标题、下载地址和所在目录会变化，不适合作为稳定身份。来源相同但目标知识库不同的分发，应另外记录目标映射。

| 数据 | 作用 |
| --- | --- |
| 扫描批次、配置修订 | 说明本次扫描依据 |
| 输入游标、输出游标 | 支持续扫与核对 |
| 来源文档编号 | 区分新增与已有文档 |
| 源版本或内容摘要 | 判断正文是否变化 |
| 元数据与权限修订 | 判断标题、标签、授权是否变化 |
| 最后发现批次 | 支持完整全量扫描后的缺失核对 |
| 候选快照 | 固定任务受理时看到的版本与操作 |

源版本可能是不可排序的字符串。只有来源协议保证单调递增时才可比较大小；否则应使用本地接收序号、当前权威版本确认或冲突检查，不能对版本字符串做随意字典序排序。

## 全量初始化流程

1. 固定来源范围、配置修订和本次扫描时间，建立运行中批次。
2. 按分页协议遍历目录，将每页结果持久化到本批次候选集合。
3. 对同一来源文档去重，记录文档版本、元数据、权限和发现时间。
4. 扫描完成后标记“枚举完整”，汇总新增、变更和疑似缺失项。
5. 将候选转换为可执行任务；批次可逐页登记任务，但不能据未完成扫描执行缺失删除。
6. 保存批次统计和可恢复位置，推进已安全受理的扫描进度。

若来源没有一致性快照，扫描期间文档移动和更新可能引发重复或遗漏。可用重叠扫描窗口、稳定排序和后续对账降低影响，不能承诺单轮绝对一致。

## 增量扫描与游标规则

游标表示读取进度，不等于所有目标文档已处理成功。可以在“该页候选和任务已可靠登记、可独立重试”之后推进受理游标；目标成功水位另外记录。这样单个坏文档不会永久卡住所有新增内容，也不会因游标提前推进丢失未登记事件。

时间戳扫描应处理相同时间的多条数据，使用稳定次序或回扫重叠区间配合去重。不得只用“更新时间大于上次最大时间”就忽略同一时间点的后续记录。

## 变更分类

| 比较结果 | 后续动作 |
| --- | --- |
| 没有目标映射 | 新增入库 |
| 正文版本变化 | 创建内容更新任务 |
| 正文不变、标题或标签变化 | 元数据更新 |
| 文档权限变化 | 优先更新访问控制，并触发索引权限刷新 |
| 明确的源删除或下线事件 | 停用或删除任务 |
| 本次列表没有出现 | 作为疑似缺失，确认后才执行下线 |
| 版本与元数据都相同 | 无需重建，可记录已核对 |

正文与权限同时变化时，收紧权限应先在访问层生效；内容重建不能阻挡撤权。

## 删除与缺失判定

只有来源明确提供删除事件，或完整扫描后经过权限、过滤范围和来源可用性核对，才可认定文档已退出同步范围。授权缩小、分页失败、目录移动、临时错误都可能造成“没看到”。

对疑似缺失项可再次查询单文档或在后续完整扫描确认。具体等待时间由业务决定；一旦确认无权继续使用，应先停止目标问答可见性，再安排物理清理。

## 异常与恢复

| 异常 | 恢复动作 |
| --- | --- |
| 中途分页失败 | 批次不标完整，从检查点续扫或重扫去重 |
| 游标过期 | 记录原因，建立新全量批次并与旧映射对账 |
| 收到重复变更通知 | 按来源身份、版本和操作归并 |
| 旧事件晚到 | 校验当前目标版本和来源权威状态，避免回退 |
| 下载时源内容已变更 | 重新取目标版本或登记新的变更，不能把新内容标为旧版本 |

## 业务示例与验收

一次扫描有 5 页数据，在第 4 页中断。前 3 页登记的更新可以继续执行，但未出现的历史文档不能批量删除。恢复后收齐 5 页，确认范围未变化，再处理仍然缺失的记录。

| 验收输入 | 预期 |
| --- | --- |
| 同一更新时间跨两页 | 全部文档均有记录，无漏项 |
| 扫描中断 | 批次状态和恢复点可查，无误删除 |
| 标题变化、正文不变 | 生成元数据任务，不重复解析 |
| 权限变更、正文不变 | 仍能识别并收紧授权 |
| 源版本为随机字符串 | 不以字符串大小判断新旧 |
| 事件乱序到达 | 有效版本不被旧任务覆盖 |

## 实施决策

确定来源的分页一致性、游标有效期、版本语义、删除事件可靠性、缺失复核方式，以及任务登记与游标推进的事务边界。
