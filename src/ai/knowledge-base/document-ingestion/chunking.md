# 内容清洗与切分

清洗去除影响阅读和检索的噪声，切分把长文档组织成可召回的知识片段。目标是让一个片段能表达可理解的业务事实，并保留还原上下文的线索。所属场景：[文档上传入库](./README.md)。

## 输入、输出与职责

输入包括标准内容、标题层级、表格结构、来源定位和切分规则版本；输出包括片段正文、片段顺序、来源区间、上级章节和必要元数据。知识维护人员抽查业务完整性，检索负责人评估片段是否适合典型问题。

切分完成表示“知识单元已准备好”，不表示索引已可用。片段必须归属于明确的内容版本与处理版本。

## 清洗规则

| 内容 | 处理原则 |
| --- | --- |
| 重复页眉、页脚、页码 | 可按识别规则去除，但保留原文定位 |
| 连续空白、乱码、断行 | 规范表达，记录不可自动修复的问题 |
| 目录 | 可用于结构识别，避免大量目录片段干扰正文召回 |
| 数字、单位、否定与条件 | 保留，禁止为了“简洁”随意改写 |
| 表格、代码、公式 | 按语义单元处理，不能当普通句子任意打断 |
| 重复条款 | 结合章节与适用范围判断，不仅凭文本相似度删除 |

跨文档内容相同也可能属于不同制度、地区或权限范围。可以在检索阶段去重展示，不能因此删除来源和访问边界。

## 切分业务流程

1. 读取经过质量检查的标准内容，并固定本次使用的规则版本。
2. 以章节、段落、列表和表格为第一层边界，优先保持自然语义。
3. 对超过模型输入或处理上限的内容进一步分组；必要时重复表头、章节标题和适用条件。
4. 对过短且依赖上下文的段落，与相邻内容合并，避免只有“详见上表”的孤立片段。
5. 按需要设置相邻片段的重叠，减少跨边界问题，但避免重复占满检索结果。
6. 生成片段标识、顺序、来源区间和父章节关联；应用文档的权限与版本信息。
7. 校验片段数量、空片段、最大长度、元数据完整性和来源覆盖情况。
8. 抽取典型问题检查片段是否保留回答所需条件，再交给索引模块。

具体长度按所用模型的 token 计算口径和真实样本确定，不把字符数直接当作 token 数，也不预设一种长度适用于全部文档。

## 常见业务内容的拆分方法

| 内容 | 建议组织方式 | 主要风险 |
| --- | --- | --- |
| 制度与操作规范 | 标题路径 + 条款 + 适用条件 | 条件与结论分离 |
| FAQ | 问题与答案作为整体 | 只有答案、失去问题语义 |
| 产品说明 | 产品身份 + 参数或操作章节 | 不同型号的参数混淆 |
| 价格与服务表 | 表头 + 适量完整行 + 单位和备注 | 价格脱离适用范围 |
| 故障排查 | 症状 + 判断条件 + 操作步骤 | 步骤被截断，顺序丢失 |

父子片段设计可以用较小片段召回，再补充所属章节，但补充内容仍需做权限、长度和有效版本检查。不能因为同属一章就无条件送入全部内容。

## 核心数据

片段至少能够关联文档、内容版本、处理版本、片段序号、正文、标题路径、来源定位和访问标签。片段标识应在同一处理版本内稳定；重新切分可以生成新的一组标识，不应覆写历史引用所指向的内容。

原文标题、业务标题和章节标题承担不同职责：前两者描述文档，章节标题用于解释片段位置。界面可组合展示，但数据上保留各自含义。

## 异常与恢复

空文档不能通过制造“无内容”片段进入索引。切分数量异常增多时，应检查页眉去重、表格转换和断句规则。任务中断后按处理版本重试，只有完整通过检查的一组片段才允许向后发布。

发现错误规则时，保留当前有效索引，创建新的处理版本并重新切分；新版本校验成功后切换。失败产物可以清理，但必须避免删除当前有效版本仍在使用的片段。

## 业务示例

原文为：“在保修期内，非人为损坏的产品可免费维修；人为损坏需收费。”如果拆成“产品可免费维修”和“人为损坏需收费”，第一片段缺少条件，容易误答。可将整条规则作为一个单元，再带上“售后服务 / 保修范围”的标题路径。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 条件句接近长度边界 | 条件、否定和结论保持可关联 |
| 大表格拆成多个片段 | 每个片段可识别表头、单位与适用产品 |
| 两份不同权限的重复文档 | 保留各自文档身份和权限 |
| 重新运行同一处理任务 | 不产生重复可用片段 |
| 切分策略升级 | 能比较旧新结果，失败时旧版本仍可用 |
| 任意命中片段 | 能找到来源文档及对应位置 |

## 实施前需要确定

确认不同文档类别的切分策略、长度预算、是否使用父子片段，以及哪些样本必须由业务人员复核。策略调整应进入[检索效果评估](../quality-operations/retrieval-evaluation.md)。
