# 向量化与索引构建

本模块将知识片段写入检索设施，并判断它们是否已经具备对外服务条件。向量化提供语义检索表示，关键词索引支持术语、编号和明确文本匹配；具体启用哪些能力取决于检索方案。所属场景：[文档上传入库](./README.md)。

## 业务目标与输入输出

输入是通过检查的完整片段集合、访问元数据及索引配置。输出是可核对的索引构建记录，以及经过发布确认的有效索引版本。知识管理员关心文档能否搜到，运维人员关心积压和失败，业务审核人员决定待审核内容何时发布。

索引成功与发布成功分别记录。审核未通过、权限已失效或文档已停用时，即使片段已写入检索服务，也不能参与普通问答。

## 索引构建流程

1. 固定文档、内容版本、处理版本及嵌入模型配置，建立索引构建批次。
2. 检查片段长度和必要元数据，按服务限制分批计算向量。
3. 保存每批执行结果；对可重试失败退避重试，避免因局部失败重复计算整份文档。
4. 写入关键词、向量及业务过滤字段，使用确定的片段映射识别重复写入。
5. 核对预期片段数、实际成功数、缺失项、版本和权限字段。
6. 等待检索服务达到可读取状态，使用代表性片段或已知问题做可见性检查。
7. 满足完整性、质量和审核要求后，检查文档仍允许发布，并切换有效版本。
8. 标记任务成功，触发状态通知；旧版本按保留策略退役和清理。

接口“已接受写入”可能只是受理异步任务，应查询实际完成结果。不要以一次 HTTP 成功响应替代检索侧核对。

## 索引与版本数据

| 数据 | 业务作用 |
| --- | --- |
| 文档、内容版本 | 确定内容来源 |
| 处理版本、索引构建编号 | 区分解析或切分策略重建 |
| 片段标识与外部索引标识 | 支持查询、重试、更新和清理 |
| 嵌入模型标识、维度、规则版本 | 保证查询侧与文档向量兼容 |
| 租户、知识库、文档状态、权限版本 | 限定可检索范围 |
| 预期数、成功数、失败数 | 证明构建完整程度 |
| 生效时间、有效版本指针 | 决定线上读取哪一组内容 |

不同模型得到的向量不能仅因维度相同就视为可互换。模型切换时需要新的索引构建和匹配的查询配置，经评估后发布。

## 发布与一致性规则

本专栏基线为整份文档版本发布：若预计有 100 个片段，仅 98 个成功，保持“索引未完成”，不把缺失条款的版本当完整版本发布。特殊场景允许部分发布时，必须显式记录覆盖范围并在产品中告知。

关键词与向量检索可以逐步完成，但发布所依赖的检索通道应满足同一版本要求。如果允许单通道降级，必须有明确策略和可观测状态，不能让两个通道混入旧新内容后看似正常。

版本切换要有条件检查：期望旧版本仍匹配、待发布版本仍是允许的目标、文档未被停用、权限仍有效。数据库与检索服务不具备原子切换能力时，可通过新旧版本并存和查询侧有效版本校验达到业务一致性。

## 异常、补偿与费用

| 异常 | 处理 |
| --- | --- |
| 模型限流或短暂不可用 | 控制并发、延迟重试，记录累计调用成本 |
| 单个片段持续失败 | 定位长度或内容问题，不无限重试整份文档 |
| 部分写入成功 | 按片段映射补齐，再核对全量 |
| 写入成功但本地确认失败 | 查询外部结果，避免无条件新建重复索引 |
| 发布时发现文档已删除 | 取消发布，加入残留索引清理 |
| 任务显示成功但搜不到 | 检查索引可见性、过滤条件与有效版本 |

内容摘要可用于本处理范围内避免重复计算，但缓存键还要包含模型与规范化规则。跨租户复用必须符合隔离设计，不能因省成本暴露其他租户的数据。

## 业务示例

售后规范 v1 已可用，v2 共 80 个片段，其中两片段向量化超时。系统保留 v1 继续提供服务，显示“更新处理中：78/80”。补齐后检索核对通过并切换为 v2；如果 v2 涉及立即停止使用旧政策，应先停用 v1，再等待 v2 发布，不能为了可用性继续回答失效政策。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 所有片段成功 | 索引数量和版本可核对，代表问题可命中 |
| 部分写入失败 | 文档不误报可用，重试后无重复片段 |
| 切换嵌入模型 | 查询和索引配置一起迁移，旧版本可回退 |
| 构建期间删除文档 | 迟到结果不能重新激活文档 |
| 新版本失败 | 原有效版本按业务规则保留，不被半成品覆盖 |
| 无原版本的新文档失败 | 状态为失败或待重试，不能参与问答 |

## 实施前需要确定

确认完整性门槛、发布是否需要审核、索引刷新等待机制、旧版本保留期、模型配额，以及模型或检索服务变更时的回退方式。
