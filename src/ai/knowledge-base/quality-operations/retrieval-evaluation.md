# 检索效果评估

检索评估判断回答所需证据能否被找到、排到合理位置，并且始终符合权限和版本约束。它应能定位问题发生在解析、切分、召回、过滤还是排序。所属场景：[质量评估与运营](./README.md)。

## 评估输入与粒度

输入包括基准问题、知识快照、参考证据、身份权限、检索策略和实际候选。评估可按文档或片段进行，但报告必须注明粒度。

切分策略变化会改变片段编号，因此比较新旧切分时，参考证据宜使用文档版本和原文区间映射，而不是只要求命中特定旧片段编号。

## 指标口径

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 文档命中率@K | 前 K 条包含至少一个参考相关文档的问题数 / 有参考文档的问题数 | 衡量是否找到线索 |
| 召回率@K | 每题前 K 条覆盖的相关证据数 / 该题标注相关证据总数 | 再报告逐题平均，说明标注覆盖限制 |
| 精确率@K | 前 K 条中相关候选数 / 实际返回候选数 | 本专栏采用实际返回数作分母，必须同时报告返回量 |
| 首条相关结果倒数排名 | 首个相关结果位次的倒数，无命中记 0 | 对样本平均后衡量排序位置 |
| 无证据误召回率 | 无答案问题中被判为有充分证据的问题数 / 无答案问题数 | 关注阈值与错误自信 |
| 越权或失效候选数 | 本轮返回的不允许访问或已失效候选数量 | 严重问题应独立阻断验收 |
| 延迟 | 检索阶段耗时分布 | 说明是否含向量计算和排序 |

没有候选时，相关样本的精确率按本基准约定记 0；某类样本分母为零时报告“不适用”，不能显示为 100%。这些定义是本专栏的报告口径，使用第三方评估工具时需核对其分母与聚合方式。

## 执行流程

1. 固定问题集、知识快照、测试身份、模型、索引和参数版本。
2. 运行原问题理解与检索链路，记录各通道原始候选。
3. 记录过滤前后的文档身份、版本、排序和排除理由；诊断数据保存在受控环境。
4. 依据人工确认的参考证据判断相关性与覆盖。
5. 分别计算召回阶段和重排序后的结果。
6. 按业务类别、角色、知识库、文件类型拆分统计。
7. 对失败样本分类，提出对应改进，再使用独立验收集验证。

## 失败原因定位

| 现象 | 优先核对 |
| --- | --- |
| 参考正文在索引中不存在 | 解析缺失、切分失败或索引未发布 |
| 正文存在但未召回 | 表达差异、编号分词、向量配置 |
| 召回后被过滤 | 元数据、权限、生效期或范围选择 |
| 召回有证据但排序很后 | 重排序模型、候选噪声、重复片段 |
| 命中文档但缺关键条款 | 片段覆盖不足、表格或条件被拆散 |
| 召回了其他租户或旧版 | 隔离与发布一致性缺陷，先修复再调相关性 |

不能仅通过增大 K 掩盖检索质量问题。更多候选可能增加噪声、排序成本和上下文压力，应同时检查最终证据覆盖与延迟。

## 对比实验规则

每次尽量只改变一个明确因素，如切分、嵌入模型或召回融合策略；如果组合升级，应列出全部变化并保留可回退版本。候选量与上下文预算要可比。

同一版本存在随机性或外部波动时，可重复运行并报告波动范围。平均分提升但关键业务类别退步时，应单独评审，不能只按总平均决定上线。

## 算例

某题标注 4 条相关证据，实际返回 5 条，其中覆盖 3 条相关证据，首条相关结果在第 2 位。则该题召回率为 3/4，精确率为 3/5，倒数排名为 1/2，文档命中计为命中。若这 3 条仍缺少回答必须的例外条件，业务完整性仍可能不合格。

此例仅解释计算方式，不代表项目实测效果。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 修改切分导致片段编号变化 | 仍能通过原文区间比较证据覆盖 |
| 某类没有样本 | 标记未覆盖或不适用 |
| 总分提升但越权出现 | 不通过验收 |
| 检索失败样本 | 计入运行失败并单独报告，不能当作正常无答案 |
| 增大候选数 | 同时比较精确度、最终覆盖、延迟和成本 |
| 参考证据不完整 | 标明标注边界，复核新增相关证据 |

## 实施决策

确定评估粒度、K 的取值、相关性标注规则、分母与聚合方式、分业务门槛，以及哪些隔离或失效问题必须阻断发布。
