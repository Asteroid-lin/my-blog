# 运行监控与成本优化

运营需要同时知道知识是否及时更新、问答是否可靠、失败能否恢复、资源是否花在有效业务上。本模块把离线质量评估与线上任务、问答和费用记录连接起来。所属场景：[质量评估与运营](./README.md)。

## 观察对象与责任

知识维护人员处理内容质量，集成负责人处理来源授权和同步差异，检索负责人处理召回效果，运维处理服务和积压，租户负责人确认配额与投入。指标必须能追到具体租户、知识库、批次或请求，同时遵守访问权限。

## 指标与口径

| 领域 | 重点指标 | 解读边界 |
| --- | --- | --- |
| 入库 | 受理量、成功量、失败量、各阶段耗时 | 区分文件上传成功与知识发布成功 |
| 同步 | 最近成功扫描、版本延迟、积压、回写失败 | 有扫描心跳不代表所有文档已更新 |
| 恢复 | 过期租约、重试量、待人工数、清理残留 | 关注长期无进展，而非只看任务存活 |
| 问答 | 完成率、失败率、无证据率、拒答率 | 中断与用户取消单独分类 |
| 延迟 | 首次响应、首个有效回答片段、完整回答耗时 | 指标起止点不同，不可混算 |
| 质量 | 投诉原因、抽检正确性、引用问题、版本问题 | 点赞率只能作为辅助信号 |
| 隔离 | 授权拒绝、撤权传播、越权测试结果 | 严重异常独立处理 |
| 成本 | 解析量、嵌入量、输入输出 token、存储与请求量 | 包含失败、重试、评估和重建消耗 |

成功率的分母、时间窗口和排除规则应固定。用户取消不应被静默消失，应独立报告。P50、P95 等延迟分位数需要足够样本，低流量时同时显示样本数和实际范围。

## 端到端追踪

上传请求关联文档、版本与处理任务；同步批次关联候选、任务及回写；问答请求关联范围、召回、排序、生成和引用。日志记录阶段起止、结果类别、耗时、版本和外部请求编号。

一般日志不直接保存全文、凭据和签名地址。需要内容抽检时使用受控样本与访问审计，并为其设定保留周期。

## 告警与处置流程

1. 为业务影响建立告警，如核心知识超时未更新、问答持续失败、撤权未传播。
2. 按租户、知识库和错误类别归并，避免同一故障产生大量重复告警。
3. 指定负责人及处置入口，附请求或任务编号和最近变更。
4. 先限制影响，例如暂停错误发布、阻断失效知识、降低重试并发。
5. 核对来源、授权、索引、模型和任务状态，定位责任阶段。
6. 修复后验证代表问题和受影响文档，再解除限制。
7. 将根因、恢复过程和防复发样本纳入记录。

阈值应结合业务更新时限、流量和服务预算制定。本文不给出未经测量的可用性或时延承诺。

## 成本归集与优化

将一次业务意图的所有尝试关联起来，区分有效处理、重复调用、失败重试和策略重建。每次成功问答平均成本可以用同一窗口内归集的相关费用除以成功完成数，但需要明确是否包含失败、存储和固定费用；分母为零时标记不适用。

| 优化动作 | 需要同时验证 |
| --- | --- |
| 避免重复入库与重复向量化 | 幂等正确，版本与权限不混用 |
| 调整片段长度 | 关键条件不丢，召回与回答质量不下降 |
| 减少上下文冗余 | 多问题证据仍完整 |
| 使用模型分层 | 复杂问题与高风险类别仍符合门槛 |
| 缓存可复用结果 | 租户、范围、版本、撤权正确失效 |
| 合理安排全量重建 | 不占满正常任务资源，存在回退方案 |

压缩成本不能通过取消权限检查、忽略失败或继续使用失效内容实现。外部单价从账单或当前合同获取，文档中的公式不代表任何供应商报价。

## 运营闭环

用户反馈应可选择“内容过期、未回答、答案错误、引用错误、权限问题、响应慢”等原因。负责人先核对原问题、证据和版本，再归类为内容、检索、生成或系统问题。

修复后将案例加入回归集，验证原问题与相邻条件问题。形成“反馈 → 归因 → 改进 → 评估 → 发布 → 观察”的闭环，并保留失败改进记录。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 来源停止更新但服务仍在线 | 版本延迟或扫描失效可告警 |
| 回写大量失败 | 与目标入库失败分开统计 |
| 重试风暴 | 能看到费用和并发异常，并限制影响 |
| 一类问题质量下降 | 分类指标能发现，总平均不会掩盖 |
| 缓存优化上线 | 同时通过撤权、版本与正确性回归 |
| 无成功请求窗口 | 平均成功成本不显示虚假数值 |

## 实施决策

确定业务服务目标、告警负责人、预算与配额、成本归集口径、日志留存、线上抽检范围和变更回退条件。
