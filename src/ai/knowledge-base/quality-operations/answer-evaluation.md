# 回答质量与引用评估

回答评估检查最终答案是否正确、有依据、完整且符合用户访问范围。语言流畅、引用存在或用户点赞，都不能单独证明业务正确。所属场景：[质量评估与运营](./README.md)。

## 评估对象

一条完整记录包含原问题、必要历史、测试身份、实际检索证据、模型输入范围、答案、引用映射、策略版本和执行状态。评估同时看“给用户的结果”与“支撑结果的依据”。

基准答案采用业务要点，不要求文字完全一致。金额、日期、资格条件、否定和例外属于关键事实，不能被宽松的语义相似度掩盖。

## 评价维度

| 维度 | 判断问题 |
| --- | --- |
| 正确性 | 结论与适用版本中的业务规则是否一致 |
| 证据支持 | 关键事实能否从本轮获准证据中得到支持 |
| 完整性 | 问题各部分、适用条件和重要例外是否覆盖 |
| 引用准确性 | 引用的具体位置是否支持邻近结论 |
| 引用覆盖 | 需要证据的关键结论是否给出了可核对依据 |
| 范围与时效 | 是否混入其他产品、地区、租户或失效规则 |
| 无答案行为 | 是否在证据不足时澄清、部分回答或拒答 |
| 可读与可操作性 | 表达是否清楚，步骤是否完整且顺序合理 |

## 评估流程

1. 固定知识快照、样本、提示规则、模型配置和检索版本。
2. 保存每次实际输出，不以“重新生成后正常”覆盖原失败。
3. 先检查越权、失效来源、编造金额与错误操作等严重问题。
4. 按要点逐项检查结论、条件、例外和证据。
5. 打开引用映射核对来源位置；分别验证引用内容与点击权限。
6. 判断该问题本应回答、澄清、部分回答还是拒答。
7. 汇总分项结果与业务类别，标记失败归因。
8. 复核争议并形成发布建议，保留人工确认记录。

评价模型可辅助初筛和发现差异，但不是业务真值。其判定也需要抽查、固定版本，并避免直接把待评答案中的指令当作评分要求。

## 建议评分方式

可对每个维度记录“通过、部分通过、不通过、不适用”，并附失败证据。若使用数值分数，必须说明每档含义、权重、样本数和聚合方式。

将严重问题作为独立门槛：跨租户泄露、引用无权访问内容、把已失效规则作为当前制度、编造关键业务限制等，不能靠其他维度的高分抵消。具体阻断标准由项目业务与安全负责人确认。

## 拒答与可回答性

| 真实情况 | 正确行为 | 常见错误 |
| --- | --- | --- |
| 证据充分 | 给出有条件的答案 | 无必要地拒答 |
| 缺少用户条件 | 澄清或列出有证据的分支 | 猜测用户情况 |
| 部分有证据 | 回答可确认部分并说明缺口 | 把缺口编成完整答案 |
| 无相关知识 | 说明当前范围证据不足 | 用常识编造企业制度 |
| 证据冲突 | 展示冲突并请求确认 | 任选一条当定论 |
| 系统失败 | 说明本次未完成 | 把故障伪装为无知识 |

报告应同时观察错误回答和过度拒答。单纯提高拒答率可能减少幻觉，但也会让有答案的问题无法完成。

## 失败归因

若证据本身缺失，优先回到解析与检索；证据正确但答案误读，检查生成规则与模型；答案正确但引用错位，检查引用映射；旧版制度混入，检查发布与过滤；历史撤权内容被复用，检查会话和缓存边界。

记录根因与修复入口，避免所有问题都归为“模型不够强”。

## 业务示例

原文规定“非人为损坏、在保产品免维修费，寄送运费由客户承担”。答案“在保维修免费，运费也免费”属于关键错误；答案“在保且非人为损坏免维修费”遗漏运费问题，属于不完整；答案完整但引用指向产品参数页，属于引用错误。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 同一结论不同自然表达 | 按要点一致性判定 |
| 引用存在但不支持结论 | 判引用或证据支持失败 |
| 回答流畅但金额编造 | 关键事实失败，不能用流畅分抵消 |
| 无答案问题合理拒答 | 计为符合预期行为 |
| 有答案问题全部拒答 | 可用性不合格 |
| 模型评分与业务专家冲突 | 进入人工复核，保留裁定依据 |

## 实施决策

确定评分维度、严重错误门槛、人工抽检比例、评分模型使用边界及发布责任。离线评估通过后仍需受控上线观察，不能据此保证所有真实问题都正确。
