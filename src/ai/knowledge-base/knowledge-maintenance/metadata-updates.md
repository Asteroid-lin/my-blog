# 标题、标签与元数据更新

元数据描述文档是什么、属于哪类、适用于什么范围、来自哪里。正文不变时，元数据仍可能影响展示、检索、权限和业务适用性，因此需要按影响分类处理。所属场景：[知识更新与下线](./README.md)。

## 字段分类

| 类别 | 例子 | 影响 |
| --- | --- | --- |
| 展示信息 | 业务标题、摘要、封面 | 列表、引用、搜索展示 |
| 来源信息 | 原始文件名、来源文档标识、来源链接 | 下载、追溯和同步映射 |
| 检索信息 | 分类、关键词、产品型号 | 检索过滤与相关性 |
| 适用信息 | 地区、业务生效时间、适用对象 | 哪些问题可使用此文档 |
| 权限信息 | 可读用户组、保密级别 | 授权与访问边界 |
| 管理信息 | 负责人、维护说明 | 运营与责任追踪 |

分类不应让所有字段走完全相同的更新路径。来源身份通常不能被随意修改；权限与适用条件变化需要更严格的检查。

## 标题与文件名

业务标题面向列表、检索、Markdown 展示和引用，例如“寄修服务规范”。原始文件名用于还原来源、下载和文件处理，例如“售后操作手册_发布版.pdf”。

修改标题不会自动重命名原始文件，也不应改变文档身份。替换文件时保留每个内容版本的原始文件名。后端调用解析器时按真实文件类型和文件名处理，不能因为标题没有扩展名就推断文件格式。

## 更新流程

1. 操作者选择文档并提交需要改变的字段、期望修订和修改理由。
2. 校验字段级权限、取值范围、引用字典和文档当前状态。
3. 比较变化，明确哪些属于展示、检索、适用条件或权限。
4. 保存新的元数据修订，并可靠登记副本更新事项。
5. 更新列表、搜索索引、片段元数据、引用展示或缓存。
6. 对权限收紧和失效条件立即限制访问，再异步刷新副本。
7. 核对各必要副本，标记完成或显示待同步差异。

只提交部分字段时，应明确“未提供”“清空”和“设置值”的区别，避免未填字段被误删。批量修改返回逐项结果，不能只报告一个总成功。

## 是否需要重建内容

| 变更 | 建议动作 |
| --- | --- |
| 只改列表展示标题 | 更新展示与引用元数据 |
| 标题参与向量化输入 | 重建受影响的向量或处理版本 |
| 标签参与过滤 | 更新索引字段并验证过滤结果 |
| 文档分类仅用于管理 | 更新管理记录及相关缓存 |
| 修改业务生效时间 | 立即按新规则判断可用范围，再更新索引 |
| 权限标签变化 | 走权限变更流程，不能等待全文重建后才撤权 |

不能笼统承诺“元数据修改从不重建索引”。是否需要重建取决于该字段实际参与了哪些处理环节。

## 同步来源与字段所有权

为各字段明确权威来源：来源维护的标题可同步更新，目标系统独有的运营标签可由本地维护。若允许本地覆盖源标题，应记录覆盖规则，避免下一次扫描又改回。

字段合并可以采用来源字段与本地覆盖字段分开存储，再计算展示值。业务规则应解释“恢复跟随来源”怎样操作，不能靠人工反复修改对抗同步任务。

## 并发与恢复

基于修订号判断并发，避免一个批量操作覆盖另一人的新标签。索引更新失败时保留待同步事项并重试；页面分别显示本地已修改与检索侧已生效。

迟到的旧元数据任务只允许更新仍对应的修订，不能把当前标题或权限退回。若下游只能整文档覆盖，应先读取并合成当前各维度数据，或对写入串行化。

## 业务示例

将“售后说明”改为“X200 寄修说明”，同时新增型号标签 X200。标题在管理页面立即更新，但过滤字段还未刷新时，应显示检索元数据处理中。若标题曾参与嵌入，需要安排新处理版本；不能仅改一条数据库记录就声称全部检索结果已更新。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 修改业务标题 | 原始文件名、文档编号不变 |
| 清空可选标签 | 仅清空明确提交的字段 |
| 权限标签收紧 | 访问立即按新规则限制 |
| 索引更新失败 | 可见待同步状态，支持幂等补偿 |
| 来源标题和本地覆盖并存 | 按确定的字段所有权展示 |
| 旧修订任务晚到 | 不覆盖新元数据 |

## 实施决策

确定字段字典、字段所有权、哪些字段参与嵌入或权限、部分更新语义，以及副本更新未完成时的展示和访问政策。
